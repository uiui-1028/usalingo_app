# Epic・課題・レポートの型

## 白紙から質問しないための候補提示

Epicまたは大きな課題を作る前に、AIが依頼文、コード、既存文書から2〜3案を作る。人間は番号で1つまたは複数を選べるようにする。

### 目的の候補

1. **利用者価値**: 利用者が何を早く、安全に、簡単にできるようになるか。
2. **開発・運用成果**: 開発者や運用者が何を迷わず、繰り返し実行できるようになるか。
3. **リスク低減・学習**: 何の事故や不確実性を減らし、次の判断材料を得るか。

### 今回やらないことの候補

1. **MVP外**: 目的達成に必須でない機能や装飾を後へ回す。
2. **後続工程**: 調査中の実装、実装中の本番公開など、次の段階を含めない。
3. **安全境界外**: データ削除、本番変更、外部公開など、別の承認が必要な操作を含めない。

### AIへ任せる範囲の候補

1. **調査・提案**: 読み取り、比較、候補作成まで。変更はしない。
2. **戻せる変更**: ローカルファイル、下書き、Notion整理など、確認・修正できる変更まで。
3. **承認済み実行**: 外部書き込みや公開を含め、明示的に承認された対象だけ実行する。

候補には「これを選ぶと何を優先し、何を諦めるか」を1文で添える。人間が選ぶ前は正式文書へ確定値として書かない。

## Epic

```markdown
# 目的

[終わったときに何が良くなるか]

# やること

1. [大きな流れ]
2. [大きな流れ]

# 完了のしるし

- [ ] [確認できる条件]
- [ ] [確認できる条件]

# 今回は含めないこと

- [範囲外]

# 人間が入口で決めること

- 着手する成果: [選んだ目的]
- 今回は変えない条件: [UI、仕様、データ、安全など]

# AIが完了まで担当すること

- 調査、設計、実施、テスト、AIレビュー、修正、文書化、完了判定
- 追加の実行承認が必要な操作: [本番変更、削除、公開など。なければ「なし」]

# 根拠

- [仕様、調査、決定、コード]
```

## 課題

```markdown
# 何のため？

[短い背景と目的]

# 今回は含めないこと

- [この課題では扱わないこと]

# やること

[1つの成果物ができる作業]

# 終わりのしるし

- [ ] [具体的に確認できる条件]
- [ ] [具体的に確認できる条件]

# 関係する場所

- [ファイル、画面、Notionページ]

# 人間が入口で決めること

- owner: [human / ai / joint]
- approval: [not-needed / waiting / approved]
- 着手するか: [選択済み / 候補]
- 変えてはいけない条件: [なければ「なし」]

# AIが完了まで担当すること

- [調査、設計、変更、テスト、AIレビュー、修正、文書化]
- 追加の実行承認が必要な操作: [本番変更、削除、公開など。なければ「なし」]

# 複数AIの作業権

- worker_id: [AIごとの一意なID]
- lease_until: [タイムゾーン付き日時で現在から30分後。作業中は延長]
- work_branch: [codex/usl-番号-短い名前]
- 取得直後と重要な書き込み前に、担当が自分のままか再確認する
- 別AIの期限が有効な場合は、この課題へ触れない

# 前に必要なもの

- [課題名] または なし

# 根拠

- source: [Knowledge、仕様書、調査結果、決定記録]

# 確認方法

- [コマンド、画面操作、読み合わせ]

# 目安

[半日〜2日]
```

## 調査結果

```markdown
# 調べたこと

# 確認できた事実

# まだ分からないこと

# 選択肢

# おすすめ

# 次の課題
```

## 決定記録

```markdown
# 決めること

# 選択肢

# 決めたこと

# 理由

# 影響する場所

# 見直す条件
```

## 完了レポート

```markdown
# 結果

[先に結論]

# 変更したもの

# 確認したこと

- 実行した確認:
- 結果:

# やっていないこと

# 残っている課題

# AIレビュー結果

- 判定: [合格 / blocked]
- 受け入れ条件の証拠:
- 見つけて直した不備:
- 未確認事項と残る危険:

# 次に選べる課題

1. [おすすめ: 効果 / 時間 / 主な危険]
2. [別案: 効果 / 時間 / 主な危険]
3. [必要な場合だけ]
```

レポートは、実装済み、テスト済み、本番確認済みを同じ意味で使わない。証拠がないものは未確認と書く。

## AIレビュー単体

```markdown
# 対象

# 受け入れ条件と証拠

- [条件]: [差分、テスト、画面、データなどの証拠]

# 見つけた不備と修正

# 実行した確認

# 未確認事項と残る危険

# 判定

[合格してdone / blockedと解除条件]
```

通常の課題で「人間のレビュー待ち」と書かない。人間への確認は、着手する課題の選択か、戻しにくい操作の実行承認に限定する。
