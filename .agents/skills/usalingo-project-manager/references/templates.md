# Epic・課題・レポートの型

## 白紙から質問しないための候補提示

Epicまたは大きな課題を作る前に、AIが依頼文、コード、既存文書から2〜3案を作る。人間は番号で1つまたは複数を選べるようにする。

### 目的の候補

1. **利用者価値**: 利用者が何を早く、安全に、簡単にできるようになるか。
2. **開発・運用成果**: 開発者や運用者が何を迷わず、繰り返し実行できるようになるか。
3. **リスク低減・学習**: 何の事故や不確実性を減らし、次の判断材料を得るか。

### 今回やらないことの候補

1. **MVP外**: 目的達成に必須でない機能や装飾を後へ回す。
2. **後続工程**: 調査中の実装、実装中の本番公開など、次の段階を含めない。
3. **安全境界外**: データ削除、本番変更、外部公開など、別の承認が必要な操作を含めない。

### AIへ任せる範囲の候補

1. **調査・提案**: 読み取り、比較、候補作成まで。変更はしない。
2. **戻せる変更**: ローカルファイル、下書き、Notion整理など、確認・修正できる変更まで。
3. **承認済み実行**: 外部書き込みや公開を含め、明示的に承認された対象だけ実行する。

候補には「これを選ぶと何を優先し、何を諦めるか」を1文で添える。人間が選ぶ前は正式文書へ確定値として書かない。

## Epic

```markdown
# 目的

[終わったときに何が良くなるか]

# やること

1. [大きな流れ]
2. [大きな流れ]

# 完了のしるし

- [ ] [確認できる条件]
- [ ] [確認できる条件]

# 今回は含めないこと

- [範囲外]

# AIと人間の分担

- AIに任せてよいこと: [選択済みの範囲]
- 人間の確認が必要なこと: [判断・承認事項]

# 根拠

- [仕様、調査、決定、コード]
```

## 課題

```markdown
# 何のため？

[短い背景と目的]

# 今回は含めないこと

- [この課題では扱わないこと]

# やること

[1つの成果物ができる作業]

# 終わりのしるし

- [ ] [具体的に確認できる条件]
- [ ] [具体的に確認できる条件]

# 関係する場所

- [ファイル、画面、Notionページ]

# AIと人間の分担

- owner: [human / ai / joint]
- AIに任せてよいこと: [範囲]
- 人間の確認が必要なこと: [判断・承認事項]

# 前に必要なもの

- [課題名] または なし

# 根拠

- source: [Knowledge、仕様書、調査結果、決定記録]

# 確認方法

- [コマンド、画面操作、読み合わせ]

# 目安

[半日〜2日]
```

## 調査結果

```markdown
# 調べたこと

# 確認できた事実

# まだ分からないこと

# 選択肢

# おすすめ

# 次の課題
```

## 決定記録

```markdown
# 決めること

# 選択肢

# 決めたこと

# 理由

# 影響する場所

# 見直す条件
```

## 完了レポート

```markdown
# 結果

[先に結論]

# 変更したもの

# 確認したこと

- 実行した確認:
- 結果:

# やっていないこと

# 残っている課題

# 次に始める1件
```

レポートは、実装済み、テスト済み、本番確認済みを同じ意味で使わない。証拠がないものは未確認と書く。
