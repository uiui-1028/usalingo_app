# *【 usalingo_05_aigc_policy.md 】*

*本ドキュメントは、usalingoで提供する全てのAI生成コンテンツ（AIGC）が、ブランドの品質基準を満たし、かつApple App StoreおよびGoogle Play Storeのポリシーを遵守することを保証するために策定された、コンテンツ生成プロセスの技術的・運用的憲章である。コンテンツ生成に関わる全てのプロセス（プロンプト設計、AIによる生成、フィルタリング、人間によるレビュー）は、本ガイドラインを絶対的な基準として運用する。*

---

## ***【 usalingo_05_01｜コンテンツ品質管理フロー 】***

*usalingoのAIGCは、不適切なコンテンツの生成を未然に防ぎ、品質を担保するため、以下の4段階からなるパイプラインを通過することを義務付ける。*

---

### 【フェーズ①】入力制御 (ゲートキーパー)

**目的：** 不適切なコンテンツ生成の可能性を、AIへの指示段階で根絶する。

```yaml
# フェーズ① 入力制御 (ゲートキーパー)
name: "フェーズ① 入力制御"
purpose: "不適切なコンテンツ生成の可能性を、AIへの指示段階で根絶する。"
process_flow:
  - step: 1
    name: "生成要求の受付"
    input: "単語 / テーマ"
    output: "次のプロセスへの入力"

  # --------------------------------------------------------------------

  - step: 2
    name: "プロンプトの構築"
    process: "構造化プロンプトテンプレートを適用"
    details: "役割(Role), 厳格な制約(Constraints), ポジティブな指示(Positive Instruction)をAIへの指示に埋め込む。"
    dependency: "ポリシー準拠フレームワーク"
    output: "安全なAPIリクエストとしてAIモデルへ送信"
```

---

### 【フェーズ②】一次検証 (自動フィルター)

**目的：** AIが生成したコンテンツから、明白な規約違反を機械的に、かつ即座にふるい落とし、大量のコンテンツを高速で分類する。

```yaml
# フェーズ② 一次検証 (自動フィルター)
name: "フェーズ② 一次検証"
purpose: "AIが生成したコンテンツから、明白な規約違反を機械的に、かつ即座にふるい落とし、大量のコンテンツを高速で分類する。"
process_flow:
  - step: 1
    name: "入力受付"
    input: "AIからの生成物 (JSON)"

  # --------------------------------------------------------------------

  - step: 2
    name: "自動検証処理"
    process: "フィルタリング処理 (サーバーレス関数)"
    details: "テキストデータに対して、以下の検証を自動実行する。"
    dependencies:
      - "NGワードリスト (usalingo_main.pdf)"
      - "有害性判定API (外部の有害性判定API)"

  # --------------------------------------------------------------------

  - step: 3
    name: "出力"
    output: "分類結果: [OK], [要レビュー], [却下]"
```

### ✦ **実装レベル1 (必須): キーワード・フィルタリング**

- **処理内容:** `usalingo_main`スプレッドシート [cite: usalingo_main - Google スプレッドシート.pdf] を基に作成した**NGワードリスト**と生成テキストを照合する。NGワードが一つでも含まれていた場合、その生成結果は自動的に「要レビュー」フラグを立てる。
- **技術仕様:** Supabase Functions内で、生成されたテキストデータに対し、事前に定義した正規表現パターンまたは文字列リストとのマッチング処理を実行する。
- **限界:** この方法は文脈を理解できないため、誤検知（例: `ass`ist）や検知漏れ（隠語など）が発生する可能性がある。そのため、あくまで一次スクリーニングとして位置づける。

### ✦ **実装レベル2 (将来的に推奨): APIによる有害性判定**

- **処理内容:** Google Cloud Natural Language APIの**有害コンテンツ分類**などの外部APIを利用し、生成テキストの有害性（ヘイトスピーチ、性的、暴力的など）をスコアリングする。
- **技術仕様:** 各カテゴリのスコアが事前に設定した閾値を超えた場合、自動的に「却下」または「要レビュー」として分類する。
- **メリット:** 文脈をある程度理解できるため、キーワード・フィルタリングよりも高精度な一次検証が可能となる。

### 【フェーズ③】最終承認 (人間による監査)

**目的：** 機械では判断が難しい文脈やニュアンスを人間が判断し、ブランド適合性を含めた最終的な品質を保証する。

```yaml

name: "フェーズ③ 最終承認"
purpose: "機械では判断が難しい文脈やニュアンスを人間が判断し、ブランド適合性を含めた最終的な品質を保証する。"
process_flow:
  - step: 1
    name: "入力受付"
    input: "「要レビュー」と分類されたコンテンツ"

  # --------------------------------------------------------------------

  - step: 2
    name: "人間による監査"
    process: "レビュワーによる監査"
    details: "定義されたチェックリストに基づき、コンテンツを評価する。"
    dependencies:
      - "レビュー用チェックリスト"
      - "App/Play Store規約"

  # --------------------------------------------------------------------

  - step: 3
    name: "出力"
    output: "判定結果: [承認], [修正], [却下]"

```

### ✦ **判定基準**

- **承認 (Approved):** 全てのチェック項目をクリア。
- **修正 (Edit Required):** 軽微な表現（例: 句読点、単語の選択）の調整で承認基準を満たせるもの。
- **却下 (Rejected):** フレームワークの根本的なルールに違反しており、修正が困難なもの。再生成を指示する。

## ***【 usalingo_05_02｜ポリシー準拠フレームワーク 】***

*全てのAIGCが遵守すべき、具体的かつ厳格なルールセット。プロンプト設計から人間による監査まで、全フェーズでこの基準が適用される。*

---

| カテゴリ | 抵触する可能性のある要素 | 具体的なNG例（単語/テーマ） | ✅ Usalingoでの許容/注意ライン（例文生成時の指針） |
| --- | --- | --- | --- |
| **🚫 1. 性的・冒涜的** | ・露骨な性的描写、ポルノ
・性的満足を目的としたコンテンツ
・ヌードや性的な身体部位の強調
・冒涜的な言葉、卑語 | **単語例:** sex, porn, naked, fuck, breasts, penis 等

**テーマ:** 性行為、売春、性的フェチ、過度な露出 | ・**原則生成禁止。**
・学習対象とする場合も、単語の定義や語源解説に留め、**例文での使用は一切不可**とする。
・hot や sexy 等の多義語は、性的でない文脈でのみ使用を許可する。（例: This coffee is hot.） |
| **🚫 2. 暴力・残虐的** | ・現実的な暴力の描写
・殺人、拷問、虐待、自傷行為
・テロリズム、暴力的過激主義の助長
・兵器の製造や使用の推奨 | **単語例:** blood, corpse, kill, torture, suicide, slaughter 等

**テーマ:** 殺人、戦争、虐待、テロ行為、銃乱射 | ・kill 等の単語は、Kill two birds with one stone. のような**慣用句**や、架空の物語の中など、**現実の暴力を想起させない抽象的な表現に限定**する。
・兵器や犯罪行為を美化・推奨する例文は生成しない。 |
| **🚫 3. ヘイトスピーチ・差別** | ・人種、民族、宗教、国籍、性別、性的指向、障害などに基づく差別、憎悪、暴力の助長
・特定の集団に対する中傷や非人間的な表現 | **単語例:** Nazi, Fascist、各種差別用語

**テーマ:** 特定の集団への偏見、ステレオタイプの助長、陰謀論 | ・**一切生成禁止。例外はない。**
・歴史学習の文脈で扱う場合でも、その行為を中立的または否定的に記述し、決して肯定・美化しない。
・特定の国籍、人種、宗教、性的マイノリティ等を否定的に描写する例文は厳禁。 |
| **🚫 4. 違法行為・危険な活動** | ・**たばこ、違法薬物、過度のアルコールの摂取を助長する行為**
・規制薬物（マリファナ等）の販売・助長
・爆発物、銃器の製造方法
・**飲酒運転やスピード超過などの危険行為の助長**
・**身体的危害を与えかねない賭け事やチャレンジ、デバイス使用の推奨**
・いじめ、嫌がらせ | **単語例:** 違法薬物の名称、銃器の具体的なモデル名

**テーマ:** 薬物使用の推奨、爆弾の作り方、特定の個人への嫌がらせ | ・**原則として一切生成を禁止する。**
・犯罪を描写する例文は、それがフィクション（例：推理小説の一節）であることが明確で、犯罪行為を推奨するものでない場合に限り、慎重に検討する。 |
| **⚠️ 5. デリケートな事象** | ・災害、紛争、死亡、その他の悲劇的な出来事に対する無神経な言及
・被害者やその関係者を不当に扱うコンテンツ | **テーマ:** 実際に起きた災害、事故、テロ事件、進行中の紛争 | ・実際に起きた悲劇的な出来事を、軽々しく学習例文の題材として利用しない。
・歴史的な出来事として扱う場合も、被害者への配慮を欠いた表現は避ける。 |

## ***【 usalingo_05_04｜コンテンツ管理システム 】***

*単語学習コンテンツ（単語、意味、例文など）を、半自動で効率的かつ安全に生成・管理するためのシステム仕様を定義する。本システムは、Google Spreadsheetをデータベース兼管理UIとし、Google Apps Script (GAS) を実行エンジン、外部API群をデータソースとして構成される。*

---

### **設計原則**

**責務の分離**

- 「入力」「保管」「設定」「記録」の各機能を物理的に異なるシートに分離し、独立性と保守性を確保する。

**自動化による安全性**

- IDの採番、データ間の整合性チェックなどをGASによるプログラムが担うことで、手動操作によるヒューマンエラーを徹底的に排除する。

**品質保証プロセス**

- 自動化による効率を最大化しつつ、コンテンツの最終的な品質は人間によるレビュー工程を経て保証する。

### **システム構成**

### **🔻 2.1. 設定・実行シート (`config_sheet`)**

- **`config`**: APIキー、GASの実行トリガー設定、Promptテンプレートなど、システム全体の動作を制御する設定値を一元管理する。
- **`log`**: GASの実行日時、処理内容、成功/失敗ステータス、エラーメッセージなどを記録する。

### **🔻 2.2. データ入力シート群 (`entry_sheets`)**

- **`entry_sheet_basic`**: 単語のコア情報（意味、品詞など）を登録する。
- **`entry_sheet_examples`**: 登録済みの意味IDに対し、例文などの拡張情報を追加する。

### **🔻 2.3. マスターデータシート群 (`master_sheets`)**

システムの正規データ（Source of Truth）を保管する。**GASによる書き込み専用**とし、人間による直接編集は原則禁止とする。

- `words_master`
- `meanings_master`
- `examples_master`
- 全マスターシートに `review_status` カラムを新設する。

### **🔻 2.4. 閲覧・管理用シート (`view_sheet`)**

`QUERY`関数を利用し、マスターシートのデータを人間が閲覧・レビューしやすい形式で表示する。

### **データ生成・拡充ワークフロー**

1. **【Step 0】 コア情報の初期生成 (ハイブリッドモデル)**
    1. **辞書API**をコールし、単語の多義語リストを構造化データとして取得する。
    2. 取得した各英語定義に対し、**生成AI**を用いて「日本語訳」「コアイメージ」「カテゴリ」を生成し、`entry_sheet_basic` に出力する。
2. **【Step 1】 コア情報の登録**
    1. `entry_sheet_basic` の内容をGASが読み込む。
    2. `words_master` と `meanings_master` にデータを登録し、一意のIDを採番する。
3. **【Step 2】 拡張情報の生成**
    1. 登録された意味ID（`meaning_id`）に基づき、**生成AI**が例文、コロケーション、イディオム等を生成し、`entry_sheet_examples` に出力する。
4. **【Step 3】 拡張情報の登録**
    1. `entry_sheet_examples` の内容をGASが読み込む。
    2. `examples_master` 等の対応するマスターシートにデータを登録する。

### **自動監査プロセスの定義**

データが `master_sheets` に登録された直後、GASによって以下の監査プロセスが自動実行される。

1. **【Step 1】 ポリシー適合チェック**
    - GASは、生成されたテキスト（例文、日本語訳など）に対し、`usalingo_05_02` で定義された禁止事項（ヘイトスピーチ、暴力的表現、差別的内容など）に該当するキーワードや表現パターンが含まれていないかをスキャンする。
    - このスキャンロジックの設定値（NGワードリスト等）は `config` シートで管理し、柔軟に変更可能とする。
2. **【Step 2】 ステータスの自動判定**
    - スキャンの結果に基づき、各データ行の `review_status` カラムに以下のいずれかのステータスが自動で設定される。
        - `auto_approved`: ポリシー違反が全く検知されなかった安全なコンテンツ。
        - `needs_human_review`: 禁止ではないが、デリケートな事象（ポリシー区分: ⚠️ 5.）に触れる可能性のある単語や文脈が検知されたコンテンツ。
        - `auto_rejected`: 明確なポリシー違反（ポリシー区分: 🚫 1〜4）が検知されたコンテンツ。

### **🔻 4.2. 人間による例外レビュー**

- `view_sheet` には、`review_status` が `needs_human_review` のアイテムのみを一覧表示する専用のタブ（`Review_Queue`）を設ける。
- レビュワーは、このキュー内のコンテンツのみを `usalingo_05_03｜監査チェックリスト` に基づいてレビューする。
- レビュー後、レビュワーはステータスを `manual_approved`（承認）または `manual_rejected`（却下）に変更する。

### **🔻 4.3. 本番環境への同期**

- GASによる定期バッチ処理は、`review_status` が以下のいずれかであるデータのみを本番のアプリケーションデータベースに同期する。
    - `auto_approved`
    - `manual_approved`
- `auto_rejected` および `manual_rejected` のデータは、同期対象から恒久的に除外される。
