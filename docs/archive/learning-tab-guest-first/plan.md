## 1. この計画の目的

学習タブだけに集中し、**ログインなしで最初から最後まで学習が回る状態**を作る。
デザインタブとプロフィールタブは凍結する。バックエンドは触らない。

いまの実装は3つの理由で目的から外れている。

1. `RootView` が未ログインを `AuthView` で堰き止めており、ログインしないと何も見られない。
2. 単語データが1件もアプリに入っておらず、全カードが Supabase 由来である（`StudyService` の全メソッドが `session: AuthSession` を要求する）。
3. 学習タブがウィジェットグリッドになっており、17種のブロックのうち12種が「まだできていません」アラートで終わる。

この計画で1〜3をすべて解消する。

## 4. データ方針の詳細

### 4.1 なぜローカル同梱か

「フロントだけでいい」という条件を満たせるのはこの案だけである。Supabase 匿名認証を選ぶと RLS とバックエンド変更が必要になり、学習タブの開発が認証作業に引きずられる。ローカル同梱ならサーバ待ちがゼロになり、オフラインでも動く。

引き換えに、ゲストの学習記録をアカウントへ引き継ぐ処理が別途必要になる。**これは今回のスコープに入れない**。別チケットへ切り出す。

### 4.2 Anki のどこを真似るか

| Anki の概念 | Usalingo での実装 |
|---|---|
| デッキ | `Deck`。カードの集合。今回は設定を持たない（D-8） |
| カード | `WordCard`。表 = 英単語、裏 = 意味・例文 |
| 復習キュー | `next_review_date <= 今日` のカードを期限順に取り出す |
| 新規カード | 一度も回答していないカード |
| SM-2 | **既存の `LearningProgress.marking(isCorrect:)` をそのまま使う** |

`LearningProgress` は既に SM-2 相当である（易しさ係数 1.3〜2.5、初回正解1日→2回目6日、不正解でレベル1へ戻し1日後）。**アルゴリズムを書き直す必要はない。** ユーザーIDの持ち方だけをゲスト対応にする。

### 4.3 デッキJSONの形式

同梱ファイルと、読み込み・書き出しの両方でこの形式を使う。

```json
{
  "formatVersion": 1,
  "deckId": "toeic-basic",
  "deckName": "TOEIC 頻出単語",
  "description": "TOEICでよく出る単語",
  "cards": [
    {
      "id": 1,
      "text": "revenue",
      "meaning": "収益、歳入",
      "partOfSpeech": "noun",
      "sentenceEnglish": "The company reported record revenue.",
      "sentenceJapanese": "その会社は過去最高の収益を報告した。",
      "imageAssetPath": null,
      "audioAssetPath": null,
      "tags": ["business"]
    }
  ]
}
```

既存の `WordCard` のフィールドに一対一で対応させる。学習進捗（`learning`）はJSONに含めない。進捗は端末側に別管理する。

## 5. チケット分割

上から順に実装する。T-1 と T-2 が土台であり、これが無いと以降が動かない。

### T-1 ゲスト起動：ログイン必須の解除

| | |
|---|---|
| 対象 | `UsalingoIOSApp.swift`（`RootView`）, `Features/Auth/AuthView.swift`, `App/AppState.swift` |
| 規模 | 小 |

**やること**

1. `RootView` の分岐から「`session == nil` なら `AuthView`」を撤去する。未ログインでも `AppShellView` へ直行させる。
2. `initialLearningProfile == nil` によるオンボーディング分岐も撤去する（D-2で不要）。`InitialLearningProfileView.swift` と関連モデルは削除してよい。
3. `AuthView` は全画面分岐ではなく、プロフィールタブから開くモーダルへ降格する。
4. パスワードリカバリ（`isResettingPassword`）の分岐は残す。ディープリンク経由でしか立たないため害はない。
5. `AppState` に `isGuest`（= `session == nil`）を用意する。

**受け入れ条件**

- アプリを新規インストール直後に起動し、一度もログインせずに学習タブが表示される。
- スワイプチュートリアルは従来どおり初回に出る。
- 未ログイン状態でプロフィールタブを開いてもクラッシュしない（中身は空でよい）。

---

### T-2 ローカルデータ層

| | |
|---|---|
| 対象 | `Services/` に新規追加、`Models/` |
| 規模 | 大 |

**やること**

1. `StudyDataSource` プロトコルを定義する。`StudySessionView` が必要とする操作だけを並べる。
   - `fetchStudyQueue(deckId:mode:) async throws -> [WordCard]`
   - `saveAnswer(card:isCorrect:) async throws -> LearningProgress`
   - `saveAnswerWithUndo(card:isCorrect:) async throws -> SavedAnswer`
   - `restoreLearningProgress(...)`
   - `saveTags(_:wordId:)` / `saveWordOverride(_:)`
   - **引数から `session: AuthSession` を消す。** 認証の有無は実装側の関心事にする。
2. `LocalStudyDataSource` を実装する。
   - 単語は同梱JSONから読む。
   - 進捗は端末に永続化する（`LearningProgress` を `Codable` のままファイルへ保存する。SwiftData は使わない。今回は最小構成でよい）。
   - `userId` はゲスト用の固定値（例 `"guest"`）を入れる。
   - キューの組み立ては既存 `StudyService` の `limitedStudyQueue` / `isDue` / `sortByNextReviewDateThenId` のロジックを移植する。**新規に考えない。**
3. 既存 `StudyService` は `StudyDataSource` に準拠させる形で残す（将来ログイン時に差し替えるため）。今回は使わない。

**受け入れ条件**

- ネットワークを完全に遮断した状態で、カードの取得・回答・1手戻すが動く。
- アプリを再起動しても進捗（次回復習日・正解回数）が残っている。
- `LearningProgress` の計算式に変更を加えていない。

### T-3 デッキリスト画面

| | |
|---|---|
| 対象 | `Features/Learning/LearningDashboardView.swift` を全面置き換え |
| 規模 | 大 |

**やること**

1. `LearningDashboardView` の中身をウィジェットグリッドから1列のデッキリストへ差し替える。`LearningDashboardWidget` enum と `WidgetGallerySheet` は削除する。
2. デッキ行に「新規 n ・ 復習 m」を表示する。集計は T-2 のデータ層から取る。
3. 行タップで**即座に学習画面へ遷移**する。確認シートもモード選択も出さない（D-8）。出題は既存 `StudyMode.all` 相当（期限が来た復習カードと新規カードを混ぜて出す）に固定する。
4. 長押しで編集モードに入り、並べ替えと削除ができるようにする。デッキの並び順は端末に永続化する。
5. 見た目は白黒ワイヤーフレーム（`AppStyle` の枠線中心のスタイルを使い、色は付けない）。

**受け入れ条件**

- デッキリストに同梱デッキが1件表示され、カウンタが実際の期限計算と一致する。
- 行タップ1回で学習画面が開き、1枚目のカードが出る。途中に確認画面が挟まらない。
- 並べ替えた順序がアプリ再起動後も保持される。

### T-4 デッキライブラリと入出力

| | |
|---|---|
| 対象 | `Features/Learning/` に新規追加 |
| 規模 | 中 |

**やること**

1. 「＋デッキを追加」から開くデッキライブラリ画面を作る。
2. 同梱サンプルデッキの一覧を出し、リストへ追加できるようにする。
3. `fileImporter` でJSONを読み込み、デッキとして追加できるようにする。形式は 4.3 に従う。
4. `fileExporter` でデッキをJSONへ書き出せるようにする。
5. 読み込み失敗時は理由を出す（形式不一致 / `formatVersion` 不一致 / 重複ID）。黙って失敗しない。

**受け入れ条件**

- 書き出したJSONを読み込み直すと、同じデッキが復元される。
- 壊れたJSONを読み込んでもクラッシュせず、理由が画面に出る。

### T-6 同梱サンプルデッキのデータ作成

| | |
|---|---|
| 対象 | `apps/ios-swiftui/UsalingoIOS/Resources/` |
| 規模 | 中（実装ではなくコンテンツ作業） |

**やること**

TOEIC頻出単語のデッキJSONを1本用意する。初版は100語を目安とする。

**このデッキは暫定データとして扱う。** 教材データの正本は `docs/content/source-database-v5.md` のとおり Google Spreadsheet だが、いまは書き出せない。そのため、TOEICの頻出語から100語を生成して先に形式を通し、正本が出せるようになった時点で中身だけ差し替える。

そのため、実装は**データの中身に依存してはならない**。語数・語彙・タグの有無が変わっても壊れないようにする。

- ファイル名は `toeic-basic.json` とし、`Resources/SampleDecks/` に置く。
- 差し替えを想定し、読み込み側にハードコードした語数や単語IDを持たせない。
- 例文・品詞・タグは任意項目として扱い、欠けていても表示が壊れないようにする。

**受け入れ条件**

- JSONが 4.3 の形式に適合している。
- アプリ起動時にパースエラーなく読み込まれる。
- 語数を10語に減らしたJSONへ差し替えても、アプリが正常に動く。

## 6. 実装順と依存関係

```text
T-1 ゲスト起動 ─┐
                ├─> T-3 デッキリスト ─> T-4 デッキ入出力
```
