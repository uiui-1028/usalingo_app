# オフライン学習 実行計画

作成日: 2026-09-15
対象: `apps/ios-swiftui/`

## 目的

Wi-Fi、DNS、Supabase Auth、Supabase Database のいずれが使えない場合でも、
アプリを開き、端末内の教材で学習し、回答を端末へ保存できるようにする。

## 順番

### 1. 端末優先の学習経路

- 認証処理を待たずに学習画面を開く。
- `LocalStudyDataSource` を認証状態にかかわらない学習の入口にする。
- 通信失敗は全画面エラーにせず、「オフラインで学習中」と表示する。
- アプリが前面へ戻ったとき、学習を止めずに再接続を試す。
- 一時的な通信失敗ではKeychainの保存済みセッションを消さない。

完了条件:

- 初回起動を機内モードで行っても、同梱デッキを開ける。
- 回答後にアプリを終了しても、端末の進捗が残る。
- 保存済みセッションは通信復帰後の再試行に使える。

### 2. 端末データのライフサイクル

- 退会が成功した場合だけ、端末の学習履歴、タグ、単語編集、追加教材を削除し、初期教材へ戻す。
- 退会が失敗した場合は端末の記録を残す。
- 匿名アカウントの端末スナップショットはSupabaseへ新しく送らない。

2026-09-17に再開の明示確認を受けて実装。画像・音声キャッシュは削除対象に含めない。

### 3. 公式教材の更新

- 同梱教材は常に読める状態を保つ。
- Supabaseから取得した公式教材を端末へ安全に更新する。
- 更新失敗時は最後に成功した端末版を使う。
- 画像・音声は既存ディスクキャッシュを使い、未取得メディアだけ代替表示にする。

この段階は学習記録の変更と混ぜず、別ブランチで実装する。

## 今回含めないもの

- 複数端末の同時編集を自動マージする同期エンジン
- 本番Supabaseのスキーマ・RLS・Auth設定変更
- 端末に一度も保存されていない画像・音声のオフライン取得
