# オフライン学習 実行計画

作成日: 2026-09-15
対象: `apps/ios-swiftui/`

状態: **統合保留**。第1・第2段階のコードとシミュレータテストはあるが、
既存利用者の教材・記録を保つ条件を満たすまで `main` に反映しない。

## 目的

Wi-Fi、DNS、Supabase Auth、Supabase Database のいずれが使えない場合でも、
アプリを開き、端末内の教材で学習し、回答を端末へ保存できるようにする。

## 順番

### 1. 端末優先の学習経路

- 認証処理を待たずに学習画面を開く。
- `LocalStudyDataSource` を認証状態にかかわらない学習の入口にする。
- 通信失敗は全画面エラーにせず、「オフラインで学習中」と表示する。
- アプリが前面へ戻ったとき、学習を止めずに再接続を試す。
- 一時的な通信失敗ではKeychainの保存済みセッションを消さない。

完了条件:

- 初回起動を機内モードで行っても、同梱デッキを開ける。
- 回答後にアプリを終了しても、端末の進捗が残る。
- 保存済みセッションは通信復帰後の再試行に使える。

### 2. 端末データのライフサイクル

- 退会が成功した場合だけ、端末の学習履歴、タグ、単語編集、追加教材を削除し、初期教材へ戻す。
- 退会が失敗した場合は端末の記録を残す。
- 匿名アカウントの端末スナップショットはSupabaseへ新しく送らない。

2026-09-17に再開の明示確認を受けて実装。画像・音声キャッシュは削除対象に含めない。

### 3. 公式教材の更新

- 同梱教材は常に読める状態を保つ。
- Supabaseから取得した公式教材を端末へ安全に更新する。
- 更新失敗時は最後に成功した端末版を使う。
- 画像・音声は既存ディスクキャッシュを使い、未取得メディアだけ代替表示にする。

この段階は学習記録の変更と混ぜず、別ブランチで実装する。

2026-09-17: 公式教材・既存進捗の読み取り保存、端末回答優先、利用者別の保存先を
作業ブランチに実装。通信復旧後の回答保持、再起動、別アカウントへの切替、
古い画面からの遅い保存、取得失敗時の前回版保持をシミュレータテストで確認した。
実機での通信遮断・復旧操作と本番データを使う確認は未実施であり、`main` への
統合可否はまだ保留する。

### `main` へ反映する前の必須条件（2026-09-17の監査）

- 公式デッキとカードの全表示情報（複数の意味、類義語、語源、音声を含む）を
  端末に欠落なく保存し、通信失敗時は最後に成功した版を読む。
- 既存の `user_card_progress` と利用者のタグ・単語編集を、サーバから
  読み取りで端末へ引き継ぐ。端末で回答済みのカードは黙って上書きしない。
- アカウントごとに端末の教材・学習記録を分離し、サインアウトや別アカウントへの
  切替時に前の利用者の記録を表示しない。
- 上記の切替・競合・再起動・通信失敗をテストする。

現状の `DeckFile` には公式カードの全表示情報が入らず、
`LocalStudyDataSource` の既定保存先 `GuestStudy` は利用者共通である。
第1・第2段階だけを配布すると既存のSupabase教材・進捗が画面から消えるため、
テストが通っても公開可能とは判断しない。

- 本番Supabaseのスキーマ・RLS・Auth設定変更
