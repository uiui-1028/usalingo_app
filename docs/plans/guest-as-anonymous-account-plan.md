# ゲストを匿名アカウントにする実行計画

作成日: 2026-09-07
対象: Supabase Auth と SwiftUIアプリ `apps/ios-swiftui/`
状態: 段階0・1 完了（2026-09-07）。段階2以降は未着手
判定の記録: [ゲストを「匿名アカウント」にする](../decisions/guest-is-an-anonymous-account-20260907.md)

## 1. 目指す姿

> 初めて開いた人が、登録なしで本番のデッキを10枚答えられる。あとで会員登録
> しても、その10枚は数え直されない。

これを「移送処理を書く」ではなく「同じアカウントを使い続ける」で実現する。

| | 変更前 | 変更後 |
|---|---|---|
| ゲストの正体 | 未認証（`session == nil`） | 匿名アカウント（`is_anonymous = true`） |
| 見えるデッキ | 端末の同梱サンプル | 本番の公式デッキ（会員と同じ） |
| 学習記録 | 端末のファイル | `user_card_progress`（最初から） |
| 会員登録 | 新しいアカウントを作る | いまのアカウントにメールとパスワードを**足す** |
| 引き継ぎ | バックアップとして保存するだけ | `user_id` が変わらないので**何もしなくて済む** |

## 2. 段階

順番に意味がある。入れ替えない。

| 段階 | 内容 | 前提 |
|---|---|---|
| 0 | 本番Supabaseで Anonymous sign-ins を ON にする | **完了（2026-09-07）**。`/auth/v1/settings` で `anonymous_users: true` を確認 |
| 1 | 起動時に匿名サインインし、ゲストも公式デッキを読む | **完了（2026-09-07）**。下の「確認できたこと」を見る |
| 2 | 会員登録を「匿名アカウントにメールとパスワードを足す」へ変える | 段階1 |
| 3 | 個人デッキ（`decks.owner_id`）を適用し、誰でもデッキを作れるようにする | 段階1 |
| 4 | 端末を正本とする経路を外す（サンプルJSON、バックアップ表） | 段階1〜3 |
| 5 | 放置された匿名アカウントの掃除 | 段階1 |

段階3は、すでに作ってある
[個人デッキの計画](user-owned-decks-plan.md) をそのまま使う。
`owner_id` の設計は匿名アカウントでもそのまま成り立つ（匿名も `auth.uid()` を持つ）。

## 3. 段階1: 匿名サインイン

### アプリ

- `AuthService` に `signInAnonymously()` を足す
  （`POST /auth/v1/signup` に body なし、または `/auth/v1/signup` の匿名指定）
- `AppState` の起動処理を「Keychainのセッションを復元 → 無ければ匿名サインイン」
  にする
- `isGuest` を「セッションが無い」から
  **「セッションの `is_anonymous` が true」** へ変える
- `studyDataSource` は常に `RemoteStudyDataSource` を返す

### 通信できないとき

匿名サインインは初回起動時に通信が要る。失敗したら、黙って端末モードへ
落とさない。「通信できないため、いまは始められません。再試行」を出す。
オフライン対応はM1・M2の対象外であり、中途半端に二重経路を残さない。

### 確認できたこと（2026-09-07、シミュレータと本番Supabase）

- 登録操作なしで、本番の公式デッキ「Starter Deck」が一覧に出た
- `auth.users` に `is_anonymous = true` の行が1件作られた
- 単語リストにも本番の単語（create / increase / improve …）が出た
- 匿名のまま「デッキを追加」でき、`decks.owner_id` にその匿名IDが入った
- 配信中の単語に無い99語は入れず、その件数を画面に出した

### まだ確認していないこと

- 10枚答えたときの `user_card_progress` の増加（段階2の通し確認とまとめて行う）
- 再起動後に同じ匿名アカウントが復元されること

## 4. 段階2: 会員登録で引き継ぐ

いまの新規登録は新しいアカウントを作るため、匿名のときの記録が置き去りになる。
これを「いまのアカウントを育てる」へ変える。

```text
変更前: 匿名アカウントA で学習 → signup で 新アカウントB → A の記録は B から見えない
変更後: 匿名アカウントA で学習 → A にメールとパスワードを足す → 同じ A のまま
```

- `PUT /auth/v1/user` でメールとパスワードを設定する
- メール確認が ON のため、確認が済むまでは匿名のまま学習を続けられるようにする
- すでにそのメールで別アカウントがある場合の分岐を決める。**この場合だけは
  記録が引き継げない。** 黙って捨てず、画面で理由を出す

### 確認

- 匿名で10枚答えてから会員登録し、記録が10枚のまま残る
- 会員登録の前後で `user_id` が変わらない
- 確認メールが届く前でも学習を続けられる
- 既存メールと重なったとき、理由が画面に出る

## 5. 段階4: 端末経路を外す

いきなり消さない。段階1〜3が本番で動いてから外す。

| 対象 | 判定 |
|---|---|
| `Resources/SampleDecks/` | 本番の導線から外す。テスト用としてテストターゲットへ残すか、削除するかは段階4で決める |
| `LocalStudyDataSource` | 学習の正本としては使わない |
| `user_local_study_backups` と `GuestStudyBackupService` | 役目を終える。表の削除は別の決定として扱う（データを消す操作のため） |
| `DeckLibraryView` の「同梱デッキ」「JSON読み込み」 | 個人デッキの作り方（単語を選ぶ）へ置き換える |

## 6. 危険と対処

| 危険 | 対処 |
|---|---|
| 匿名アカウントが無制限に増える | 段階5で掃除方針を決める。学習記録が0件で一定期間触られていない匿名は削除候補 |
| 端末を変えると別人になる | 仕様として明示する。会員登録を促す文言をどこに置くか段階2で決める |
| 匿名でも個人デッキを作れてしまう | 作れてよい。ただし上限（50デッキ）は匿名にも効く |
| 初回起動で通信できない | 段階3の文言で明示し、端末モードへ落とさない |
| 既存のログイン利用者への影響 | `user_id` は変わらない。段階1・2は匿名アカウントの経路だけを足す |

## 7. まだ決めていないこと

- 会員登録を促すタイミングと文言
- 匿名アカウントに個人デッキの上限を別に設けるか
