## 2. 画面の決めごと（変更しないこと）

- 画面は「背面のバナー」と「前面のシート」の2層。バナーの面は
  `WireColor.scrim`、シートの面は `WireColor.surface`。前後関係は色ではなく
  この2段の明度差と、シート上端の角丸＋枠線で示す。
- シートの高さは画面（セーフエリア込み）の **0.75 倍で固定**。ドラッグで
  伸縮させない。`WordListView.sheetHeightRatio` が唯一の定義。
- シートの中身はシートの上端まで流れ、そこで切り取られる。上端に余分な
  ヘッダーや掴み手（grabber）を置かない。
- 札の帯は**横スワイプでデッキを送る**。端は決めず、右にも左にも回り続ける
  （A→B→C→D→A→…）。通し番号をデッキ数で割った余りで札を決めているので、
  「最後の次」「最初の前」という境目が存在しない。
- 何枚目かは札の下の点の行で示す。点はデッキ1件につき1つ。
- **札の帯だけ**は戻るスワイプを止める（`backSwipeProtectedRegion`）。
  同じ指の動きにデッキ送りと画面戻りの両方は割り当てられないため。詳しくは
  6 章。

## 3. 所持デッキの取得

- 取得元は学習タブと同じにする。`LearningDashboardView` の `reload()` が
  使っている経路を確認し、同じデータソース（`appState.studyDataSource`）から
  取る。単語リスト専用の取得経路を新設しない。
- 取得は `WordListViewModel` に持たせる。`WordListView` は表示だけを担う。
  - `@Published var decks: [Deck] = []`
  - `@Published var selectedDeckID: Int?`
  - `func loadDecks(dataSource:) async`
- ゲストと未ログインでも落ちないこと。デッキが0件のときはバナーに
  「デッキがありません」の1行を出し、札は並べない。
- 取得の失敗はシート側のエラー表示と混ぜない。バナーの中で1行にとどめる。

## 4. 選んだデッキで一覧を差し替える

- `selectedDeckID` が変わったら、その `Deck` を使って
  `WordListViewModel.load(dataSource:)` をやり直す。
- 現在の `WordListViewModel` は `init(deck:)` でデッキを固定している。
  デッキを**後から差し替えられる**ように変える必要がある。ここが実装の
  本体で、`init` を変えるか、`deck` を `var` にして `load` の引数に取るかを
  最初に決めること。
- 差し替え中はシートの中身だけを差し替える。バナーの札は動かさない
  （押した札が消えたり並び替わったりしない）。
- 差し替え中の見せ方は、いまの `isLoading` のスピナーを流用する。シートの
  高さは変えない。
- 絞り込み・並べ替え・検索の状態をデッキ切り替え時にどうするかを決めること。
  推奨は「タグ絞り込みだけ解除、並べ替えと表示モードは維持」。理由は、タグは
  デッキごとに違うが、並べ替えと表示モードはユーザーの好みだから。

## 5. 選択の保存

- 画面を出て戻ったときに、前に選んでいたデッキを覚えていること。
- 保存先は `AppState` を第一候補にする（学習タブと選択を共有できるため）。
  端末に残す必要が出たら `UserDefaults` を足す。この判断は実装時に
  決定記録（`docs/decisions/`）へ残す。

## 6. ジェスチャの調停（最重要）

バナー領域には2つの横方向の操作が重なる。**同じ場所に両方は置けない**ので、
場所で分けた。

| 場所 | 横スワイプの意味 |
| --- | --- |
| 札の帯（カード3枚が並ぶ帯） | **デッキ送り**。戻るスワイプは止める |
| 点の行と、その下の注記 | **前の画面へ戻る** |
| シートの中（一覧） | **前の画面へ戻る**（行のタップは枠の中だけ） |
| シート下の浮動バー | どちらでもない（バーの操作。戻るスワイプは止める） |

- 実装は学習画面と同じ仕組み。`BackSwipeEnabler` が UIKit の対話的 pop の
  delegate を差し替え、`backSwipeProtectedRegion()` を敷いた矩形から始まった
  タッチだけを pop に渡さない。
- iOS 26 以降はコンテンツ全体で戻れるため、**保護しないと札の送りが必ず
  戻る操作に食われる**。保護は必須で、外してはいけない。
- 札のタップは `cardTapTarget` で札の枠の中だけが反応する。タップは戻る
  スワイプと競合しない。真ん中以外の札を押すと、その札まで送る。

### 点が増えすぎたときの扱い（未決）

点はデッキ1件につき1つ出している。10件を超えると点が細かくなり読めなく
なる。次のどれかを実装時に決めること。

| 案 | 備考 |
| --- | --- |
| 点を最大7つにして、両端を小さく描く（iOS標準のページ制御と同じ） | 見た目の実装が増える |
| 点をやめて「3 / 12」の数字にする | 一目で位置がわかる。省スペース |
| そのまま全部出す | 10件程度までなら成立する |

## 7. 受け入れ条件

- [ ] バナーに所持デッキが出る。0件・取得失敗でも画面が壊れない
- [ ] 札を押すとシートの単語がそのデッキのものへ差し替わる
- [ ] 差し替え中もシートの高さと位置が変わらない
- [ ] 画面を出て戻っても、選んだデッキを覚えている
- [ ] 札の帯を横スワイプするとデッキが送られ、端で止まらず回り続ける
- [ ] 点の行から始めた横スワイプでは前の画面へ戻れる
- [ ] 札の帯から始めた横スワイプでは前の画面へ戻らない
- [ ] 札の枠の外（バナーの背景）を押しても何も起きない
- [ ] `xcodebuild test` が通る
