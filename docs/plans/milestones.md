# Usalingoのマイルストーン

作成日: 2026-08-30

チケットと[製品計画](../product/plan.md)の間には、これまで層がなかった。そのため
「直せるところを直す」でチケットが積まれ、消化しても方向が生まれなかった。この文書は
その間の層を置く。**いま何をやり、何をやらないか**は、ここに書いた2つのマイルストーンで決める。

## 北極星

> 初めて開いた人が、設定なしで10枚答えて、翌日また開く。

指標の細かい定義は「決定｜配信後に見る指標と、次を決める基準を決める」で決める。

## 完了の定義

このリポジトリでは、次の3つを満たしたものだけを「完了」と呼ぶ。

1. 実機または対象環境で、1回通しで動いた
2. 関連するテストが通った
3. 確認した内容と、未確認のまま残ったことが文書に残っている

「実装した」「テストが通った」「本番で動いた」は別の意味として扱い、混ぜて報告しない。

## M1: 身内テスターがTestFlightでUsalingoを触れる

**なぜ先にやるか。** 配信の経路は、後回しにすると必ず詰まる。中身が薄くても、管を先に
一度通しておけば、以降の配信は繰り返しになる。そして配ってからでないと、何を直すべきか
の答えは推測のままになる。

| 項目 | 内容 |
|---|---|
| 終わったときの姿 | 内部テスターがTestFlightからUsalingoを入れ、初回起動から10枚答えられる |
| Notion Epic | 身内テスターがTestFlightでUsalingoを触れる |
| 含めないこと | App Store一般公開、課金、広告、学習アルゴリズムの作り直し、教材の増量 |
| 主な危険 | 中身が薄いまま配ると評価が取れず、判断を誤る。だからM2を続けて回す |

M1は既存の未完了にも依存する。

- USL-255（法務・ライセンス表示）— 人に配るなら必要。**M1に残る唯一のblocked**。状態と次の一手は [usl-255-handoff.md](usl-255-handoff.md)
- USL-245（Anki migrationの本番適用）— 適用まで学習記録のバックアップが動かない。**done**

## M2: Ankiの原本から50語を標準デッキとして配れる

**なぜ次にやるか。** Usalingoのいちばんの強みは教材そのものにある。1900語の原本はあるのに、
アプリへ載せる道がまだ通っていない。まず50語で原本からアプリまでを一度通し、そのあとは
同じ道を繰り返すだけにする。

| 項目 | 内容 |
|---|---|
| 終わったときの姿 | イラスト・例文・音声つきの50語が標準デッキとして実機に出る |
| Notion Epic | Ankiの原本から50語を標準デッキとして配れる |
| 含めないこと | 1900語すべての投入、利用者が自分の単語やデッキを作る機能、画像生成の作り直し |
| 主な危険 | 置き場所と配り方を決めずに量産すると、全部入れ直しになる。だから決定を先に置く |

## 課題の採否ルール

新しい課題は、次の順で判定する。

1. M1またはM2に要るか。要るなら `will` にして着手対象へ入れる。
2. 要らないが、いずれ必要か。`reserved` または `idea` にして、見直す条件を書く。
3. どちらでもないなら作らない。

**止めたものは、止めた記録を残す。** 記録がないものは、必ず戻ってくる。判定と停止の記録は
[../decisions/plan-scope-20260830.md](../decisions/plan-scope-20260830.md) にある。

## 進め方

- Notionの `Pro｜Usalingo｜02｜Taskspace` に、M1とM2のEpicと課題を登録済み。
- 人間は入口で着手する課題を選ぶ。選ばれたあとの可逆な作業は、AIが完了報告まで進める。
- 戻しにくい操作（TestFlightへの提出、本番Supabaseへの投入、公開設定の変更）は、
  実行の直前に人間の承認を得る。
