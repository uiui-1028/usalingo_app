# Anki準拠仕様メモ（Web版）

## 目的

このドキュメントは、Usalingo Web版をAnkiライクな学習体験へ段階的に近づけるための基準を定義する。  
Anki本体コードの取り込みは行わず、設計思想と学習アルゴリズムを参照して実装する。

## 前提

- フロントエンド: Next.js (`apps/web`)
- バックエンド: Supabase
- 既存主要テーブル:
  - `words`
  - `word_meanings`
  - `example_contents`
  - `user_learning_progress`
- 認証: Supabase Auth
- MVPでは学習セッション前にログインを必須とし、ゲスト学習は後続フェーズへ送る

## 方針（採用しないこと）

- Anki OSSのコードを本リポジトリへ直接コピーしない
- Ankiの内部データ構造や実装依存をそのまま持ち込まない
- まずはUsalingo既存DBスキーマを活かし、必要最小限の拡張で進める
  
## 方針（採用すること）

- 出題キューの考え方（新規/学習中/復習）
- 2段階評価（正解/不正解）
- 評価に応じた次回復習日の計算
- 日次学習上限（新規枚数・復習枚数）
- 学習セッションの統計可視化

## 採用・非採用一覧

### 採用（Phase 1: 実装済み/着手済み）

- `words` 由来の単語カード一覧表示
- `/study` でのフラッシュカード学習
- 2段階評価ボタン
- `user_learning_progress` への保存
- 未ログイン時の学習ページ保護

### 採用（Phase 2: 直近で実装）

- 新規/復習の1日上限
- 不正解カードの同日再出題（学習キュー内再挿入）
- 期限到来カード優先（`next_review_date <= now`）
- デッキ/タグ単位の学習対象絞り込み
- 今日の学習統計（回答数、正答率、復習残数）

### 保留（MVP後に再評価）

- ゲスト状態での本学習セッション
- ウィジェット配置・学習設定のクラウド同期
- Flutter版への仕様反映

### 採用（Phase 3: 中期）

- FSRSまたはSM-2互換パラメータを永続化して最適化
- 学習負荷の自動調整（ユーザー別）
- キーボードショートカット中心の高速学習UI
- 音声/画像のカード提示最適化

### 非採用（当面）

- Ankiの完全互換（コレクション形式、プラグイン互換）
- Ankiと同一の内部アルゴリズム再現を最優先にする方針
- 複雑なテンプレートDSLを初期段階で導入

## 学習キュー仕様（現行ベース）

1. 復習期限到来カードを先にキュー化
2. 未学習カードを上限数だけ追加
3. `不正解` は短時間後に再出題
4. `正解` は間隔とEaseを更新
5. 各回答で `user_learning_progress` を `upsert`

## `user_learning_progress` の利用方針

- 更新対象:
  - `status`
  - `last_reviewed_at`
  - `next_review_date`
  - `srs_level`
  - `easiness_factor`
  - `repetitions`
  - `interval_days`
  - `updated_at`
- 一意条件:
  - `user_id + word_id` を1レコードとして扱う

## 品質基準

- `npm run lint` と `npm run build` が通ること
- 未ログインで `/study` へ直接アクセスした場合に `/auth` へ遷移すること
- 1回答ごとに `user_learning_progress` が更新されること
- 復習期限のカードが新規カードより優先されること

## 実装判断ルール

- 迷った場合は「学習継続率を上げるか」で判断する
- 新機能は1つずつ導入し、学習体験の回帰を防ぐ
- DB変更が必要な場合は、既存マイグレーションルールに従う

## 参考情報の扱い

- 参考にするもの:

- 参考にしないもの:
