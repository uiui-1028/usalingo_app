# タスク04: 複合インデックスの追加

## 📋 概要
**優先度:** 🟡 中優先度（早めに対応すべき）

頻繁に使用されるクエリパターンに対応するため、複合インデックスを追加する。

## 🎯 目的
- 複数カラムでのフィルタリング時のパフォーマンス向上
- 頻繁なソート処理の高速化
- クエリ実行計画の最適化

## ❌ 現在の問題

```sql
-- 現在の設計（単一カラムインデックスのみ）
CREATE INDEX IF NOT EXISTS idx_meanings_on_word_id 
ON public.word_meanings (word_id);
```

**影響:**
- 複数カラムでのフィルタリング時にパフォーマンスが低下
- 特に`priority`や`theme`でのソートが頻繁な場合に遅い

## ✅ 改善案

### 1. クエリパターンの分析

#### よく使用されるクエリ例
```sql
-- パターン1: 単語IDとpriorityでの検索・ソート
SELECT * FROM word_meanings 
WHERE word_id = 123 
ORDER BY priority;

-- パターン2: 意味IDとthemeでの検索
SELECT * FROM example_contents 
WHERE meaning_id = 456 
AND theme = 'simple';

-- パターン3: デッキIDでの単語一覧取得
SELECT w.* FROM words w
JOIN deck_words dw ON w.id = dw.word_id
WHERE dw.deck_id = 789;
```

### 2. 複合インデックスの追加

```sql
-- word_meaningsテーブル: word_id + priority
CREATE INDEX IF NOT EXISTS idx_meanings_on_word_priority 
ON public.word_meanings (word_id, priority);

-- example_contentsテーブル: meaning_id + theme
CREATE INDEX IF NOT EXISTS idx_examples_on_meaning_theme 
ON public.example_contents (meaning_id, theme);

-- deck_wordsテーブル: deck_id + word_id（既存のPKで対応済み）
-- PRIMARY KEY (deck_id, word_id) が既に存在するため追加不要

-- wordsテーブル: word_textでの前方一致検索用
CREATE INDEX IF NOT EXISTS idx_words_text_pattern 
ON public.words (word_text text_pattern_ops);
```

### 3. カバリングインデックス（オプション）

```sql
-- よく使用されるカラムを含むカバリングインデックス
CREATE INDEX IF NOT EXISTS idx_meanings_covering 
ON public.word_meanings (word_id, priority) 
INCLUDE (part_of_speech_en, definition_jp);
```

### 3. パフォーマンステスト
- [ ] インデックス追加前のクエリ実行時間を測定

```sql
-- パフォーマンス測定例

-- 複合インデックスなし

-- 複合インデックス作成
CREATE INDEX idx_meanings_on_word_priority 
ON word_meanings (word_id, priority);

-- 複合インデックスあり
SELECT * FROM word_meanings WHERE word_id = 123 ORDER BY priority;
```

### 4. インデックスサイズの監視
```sql
-- インデックスサイズの確認
SELECT 
    schemaname,
    tablename,
    indexname,
    pg_size_pretty(pg_relation_size(indexname::regclass)) as index_size
FROM pg_indexes
WHERE schemaname = 'public'
ORDER BY pg_relation_size(indexname::regclass) DESC;
```

## 📊 期待される効果

### パフォーマンス改善目標
- ✅ 複数カラムフィルタリングのクエリ: 50%以上高速化
- ✅ ソート処理: 30%以上高速化
- ✅ JOIN処理: 20%以上高速化

### 注意点
⚠️ インデックスの追加によるトレードオフ:
- データ挿入・更新時のオーバーヘッドが増加
- ストレージ使用量が増加
- 必要なインデックスのみを追加すること

## 📈 推奨される複合インデックス一覧

| テーブル | インデックス名 | カラム | 用途 |
|---------|--------------|--------|------|
| word_meanings | idx_meanings_on_word_priority | (word_id, priority) | 単語の意味取得時のソート |
| example_contents | idx_examples_on_meaning_theme | (meaning_id, theme) | テーマ別例文取得 |
| words | idx_words_text_pattern | (word_text text_pattern_ops) | 前方一致検索 |
