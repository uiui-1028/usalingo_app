# タスク06: 全文検索インデックスの追加

## 📋 概要
**優先度:** 🟡 中優先度（早めに対応すべき）

pg_trgm拡張機能とGINインデックスを使用して、高速な全文検索を実現する。

## 🎯 目的
- 中間一致検索の高速化
- あいまい検索の実現
- ユーザー検索体験の向上

## ❌ 現在の問題

```sql
-- 現在の検索クエリ
SELECT * FROM words WHERE word_text LIKE 'app%';  -- 前方一致のみ高速
SELECT * FROM words WHERE word_text LIKE '%app%'; -- 遅い
```

**影響:**
- 前方一致検索は比較的高速だが、中間一致や複雑な検索が遅い
- ユーザーの検索体験が低下
- スペルミスへの対応が困難

## ✅ 改善案

### 1. pg_trgm拡張機能の有効化

```sql
-- pg_trgm拡張機能の有効化
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

### 2. GINインデックスの作成

```sql
-- wordsテーブルの全文検索インデックス
CREATE INDEX IF NOT EXISTS idx_words_text_gin 
ON public.words USING GIN (word_text gin_trgm_ops);

-- word_meaningsテーブルの日本語定義検索用（オプション）
CREATE INDEX IF NOT EXISTS idx_meanings_definition_gin 
ON public.word_meanings USING GIN (definition_jp gin_trgm_ops);

-- example_contentsテーブルの例文検索用（オプション）
CREATE INDEX IF NOT EXISTS idx_examples_sentence_gin 
ON public.example_contents USING GIN (sentence_en gin_trgm_ops);
```

### 3. 類似度検索関数の作成

```sql
-- 類似度による検索関数
CREATE OR REPLACE FUNCTION public.search_words(
    search_term TEXT,
    similarity_threshold REAL DEFAULT 0.3,
    limit_count INTEGER DEFAULT 20
)
RETURNS TABLE(
    id INTEGER,
    word_text TEXT,
    similarity REAL
) AS $$
BEGIN
    RETURN QUERY
    SELECT 
        w.id,
        w.word_text,
        similarity(w.word_text, search_term) as similarity
    FROM public.words w
    WHERE w.word_text % search_term  -- 類似度演算子
    ORDER BY similarity(w.word_text, search_term) DESC
    LIMIT limit_count;
END;
$$ LANGUAGE plpgsql;
```

## 📈 pg_trgmの機能一覧

### 1. 類似度演算子
```sql
-- % 演算子: 類似度が閾値以上
SELECT * FROM words WHERE word_text % 'apple';

-- similarity関数: 類似度を数値で取得
SELECT word_text, similarity(word_text, 'apple') 
FROM words 
WHERE word_text % 'apple';
```

### 2. 類似度閾値の設定
```sql
-- デフォルトは0.3（30%）
SET pg_trgm.similarity_threshold = 0.5;  -- 50%に変更

-- セッション単位で設定
SELECT set_limit(0.5);
```

### 3. トライグラム表示
```sql
-- 単語のトライグラム表示
SELECT show_trgm('apple');
-- 結果: {"  a"," ap",app,ple,"le "}
```

## ⚠️ 注意点

### インデックスサイズ
- GINインデックスは通常のB-treeより大きい
- データ量に応じてストレージ使用量が増加
- 定期的なインデックスメンテナンスが必要

### パフォーマンス
- データ挿入・更新時のオーバーヘッドが増加
- 小規模データセットでは効果が限定的
