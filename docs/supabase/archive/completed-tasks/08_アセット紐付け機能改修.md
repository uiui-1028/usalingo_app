# アセット紐付け機能改修

## 完了日: 2025年1月27日

## 概要
Supabaseのメディアファイル自動紐付け機能について、新しいファイル命名規則に対応した設計見直しを実施。テスト開発段階でのリスク最小化を前提に、長期的スケーラビリティを重視した関数ベースアプローチへの移行を完了。

## 実施内容

### 1. 設計見直しの分析
- 現在のシステム状況の詳細分析
- パフォーマンステストの実施（59倍の性能差を確認）
- 新しい命名規則への対応検討

### 2. MCP自動実行部分
- ✅ Edge Function `asset-linker-v3` のデプロイ
- ✅ データベース関数の作成
  - `get_audio_meaning_path(meaning_id)`
  - `get_image_example_path(example_id)`
  - `get_audio_example_path(example_id)`
- ✅ パフォーマンス最適化インデックスの作成
- ✅ 関数動作テストの実施

### 3. 手動操作部分
- ✅ 依存関係の分析と解決策の提供
- ✅ 段階的クリーンアップスクリプトの作成
- ✅ テーブル構造の変更（asset_pathカラム削除）
- ✅ ビューとトリガーの再作成

## 新しい命名規則
| 対象 | 命名規則 | 具体例 |
|------|----------|--------|
| 意味ごとの単語音声 | `audio_meaning_{meaning_id}.mp3` | `audio_meaning_251.mp3` |
| 例文の読み上げ音声 | `audio_example_{example_id}.mp3` | `audio_example_882.mp3` |
| 例文のイラスト画像 | `image_example_{example_id}.webp` | `image_example_882.webp` |

## 技術的成果

### データベース関数の最適化
```sql
-- 最適化されたパス生成関数
CREATE OR REPLACE FUNCTION get_audio_meaning_path(meaning_id INTEGER)
RETURNS TEXT AS $$
BEGIN
    RETURN 'content-audio/audio_meaning_' || meaning_id || '.mp3';
END;
$$ LANGUAGE plpgsql IMMUTABLE;
```

### テーブル構造の簡素化
- `asset_path`カラムの削除
- 不要な拡張子カラムの削除
- 依存関係の適切な解決

### Edge Function の改修
- 新しい命名規則に対応した`asset-linker-v3`
- 最適化されたエラーハンドリング
- 詳細なログ出力
