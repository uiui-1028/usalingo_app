# アセット紐付け機能改修レポート

## 概要

Supabaseのメディアファイル自動紐付け機能について、新しいファイル命名規則に対応した設計見直しを実施。テスト開発段階でのリスク最小化を前提に、長期的スケーラビリティを重視した関数ベースアプローチへの移行を推奨。

## 改修の背景

### 現状の課題
- 既存の`asset_path`カラムによる重複データ管理
- 複雑な命名規則による運用負荷
- 長期的なスケーラビリティの懸念

### 新しい命名規則
| 対象 | 命名規則 | 具体例 |
|------|----------|--------|
| 意味ごとの単語音声 | `audio_meaning_{meaning_id}.mp3` | `audio_meaning_251.mp3` |
| 例文の読み上げ音声 | `audio_example_{example_id}.mp3` | `audio_example_882.mp3` |
| 例文のイラスト画像 | `image_example_{example_id}.webp` | `image_example_882.webp` |

## 設計見直しの分析

### 1. 現在のシステム状況
- **データベース構造**: `asset_path`カラム + 関数ベースの併用
- **レコード数**: word_meanings: 1000件、example_contents: 1000件
- **使用状況**: 全レコードでasset_pathが設定済み
- **Edge Function**: 3つの関数が稼働中（asset-linker, migrate-assets, asset-linker-v2）

### 2. パフォーマンス分析結果
```
asset_pathカラム直接参照: 0.134ms (100レコード)
関数呼び出し: 7.951ms (100レコード)
パフォーマンス差: 約59倍の差
```

### 3. 設計オプションの比較

#### Option A: asset_pathカラム維持（既存方式）
**利点:**
- 高いクエリパフォーマンス
- 既存システムとの互換性
- デバッグ時の可視性

**欠点:**
- ストレージ使用量の増加
- データ整合性の課題
- 命名規則変更時の影響範囲

#### Option B: 関数ベースアプローチ（推奨）
**利点:**
- 長期的スケーラビリティ
- データ整合性の向上
- 保守性の向上
- ストレージ効率の最適化

**欠点:**
- 初期パフォーマンスオーバーヘッド
- 関数最適化が必要

## 推奨設計

### 1. データベース関数の最適化

```sql
-- 最適化されたパス生成関数
CREATE OR REPLACE FUNCTION get_audio_meaning_path(meaning_id INTEGER)
RETURNS TEXT AS $$
BEGIN
    RETURN 'content-audio/audio_meaning_' || meaning_id || '.mp3';
END;
$$ LANGUAGE plpgsql IMMUTABLE;

CREATE OR REPLACE FUNCTION get_image_example_path(example_id INTEGER)
RETURNS TEXT AS $$
BEGIN
    RETURN 'content-images/image_example_' || example_id || '.webp';
END;
$$ LANGUAGE plpgsql IMMUTABLE;

CREATE OR REPLACE FUNCTION get_audio_example_path(example_id INTEGER)
RETURNS TEXT AS $$
BEGIN
    RETURN 'content-audio/audio_example_' || example_id || '.mp3';
END;
$$ LANGUAGE plpgsql IMMUTABLE;
```

### 2. テーブル構造の簡素化

```sql
-- asset_pathカラムの削除
ALTER TABLE word_meanings DROP COLUMN audio_asset_path;
ALTER TABLE example_contents DROP COLUMN illustration_asset_path;
ALTER TABLE example_contents DROP COLUMN audio_asset_path;

-- 不要な拡張子カラムの削除（固定形式のため）
ALTER TABLE word_meanings DROP COLUMN audio_ext;
ALTER TABLE example_contents DROP COLUMN illustration_ext;
ALTER TABLE example_contents DROP COLUMN audio_ext;
```

### 3. インデックス最適化

```sql
-- パフォーマンス最適化のためのインデックス
CREATE INDEX CONCURRENTLY idx_word_meanings_id_audio 
ON word_meanings (id) WHERE audio_filename IS NOT NULL;

CREATE INDEX CONCURRENTLY idx_example_contents_id_assets 
ON example_contents (id) WHERE illustration_filename IS NOT NULL OR audio_filename IS NOT NULL;
```
