# タスク07: ストレージ階層化の実装

## 📋 概要
**優先度:** 🟡 中優先度（早めに対応すべき）

Supabase Storageのアセットを、マスタデータのIDに基づいた階層的なフォルダ構造に整理する。

## 🎯 目的
- GUI操作性の向上（200件制限への対応）
- メンテナンス性の向上
- 実装の簡素化（IDから動的にパス生成）

## 📚 背景

**Supabase GUIの制約:**
- 1フォルダあたり200件までしかファイルが表示されない
- アセット数が増加すると管理が困難になる

**現在の構造:**
```
content-images/
  ├── us_mvp_image_0001_create.webp
  ├── us_mvp_image_0002_increase.webp
  └── ... (1000件以上がフラット)

content-audio/
  ├── say-1cb36bde-da34a55d-9eef5c1d-e61163df-5c7f1ff4.mp3
  └── ... (1000件以上がフラット)
```

### 3. パス生成関数

```sql
-- IDからフォルダパスを生成する関数
CREATE OR REPLACE FUNCTION public.get_asset_folder_path(
    asset_id INTEGER,
    bucket_size INTEGER DEFAULT 200
)
RETURNS TEXT AS $$
DECLARE
    folder_start INTEGER;
    folder_end INTEGER;
BEGIN
    -- フォルダの開始・終了IDを計算
    folder_start := (asset_id / bucket_size) * bucket_size;
    folder_end := folder_start + bucket_size - 1;
    
    -- フォルダパスを返す
    RETURN folder_start || '-' || folder_end;
END;
$$ LANGUAGE plpgsql IMMUTABLE;

-- 例文イラストの完全パスを生成
CREATE OR REPLACE FUNCTION public.get_example_illustration_path(
    example_id INTEGER,
    file_extension TEXT DEFAULT 'webp'
)
RETURNS TEXT AS $$
BEGIN
    RETURN 'content-images/' || 
           public.get_asset_folder_path(example_id) || '/' ||
           example_id || '.' || file_extension;
END;
$$ LANGUAGE plpgsql IMMUTABLE;

-- 例文音声の完全パスを生成
CREATE OR REPLACE FUNCTION public.get_example_audio_path(
    example_id INTEGER,
    file_extension TEXT DEFAULT 'mp3'
)
RETURNS TEXT AS $$
BEGIN
    RETURN 'content-audio/example/' || 
           public.get_asset_folder_path(example_id) || '/' ||
           example_id || '.' || file_extension;
END;
$$ LANGUAGE plpgsql IMMUTABLE;

-- 単語音声の完全パスを生成
CREATE OR REPLACE FUNCTION public.get_word_audio_path(
    word_meaning_id INTEGER,
    file_extension TEXT DEFAULT 'mp3'
)
RETURNS TEXT AS $$
BEGIN
    RETURN 'content-audio/word/' || 
           public.get_asset_folder_path(word_meaning_id) || '/' ||
           word_meaning_id || '.' || file_extension;
END;
$$ LANGUAGE plpgsql IMMUTABLE;
```

```sql

CREATE OR REPLACE VIEW public.example_contents_with_paths AS
SELECT 
    ec.*,
    public.get_example_illustration_path(ec.id, ec.illustration_ext) as illustration_full_path,
    public.get_example_audio_path(ec.id, ec.audio_ext) as audio_full_path
FROM public.example_contents ec;

CREATE OR REPLACE VIEW public.word_meanings_with_paths AS
SELECT 
    wm.*,
    public.get_word_audio_path(wm.id, wm.audio_ext) as audio_full_path
FROM public.word_meanings wm;
```

## ⚠️ 移行時の注意点

### バックアップ
- 移行前に必ずStorageのバックアップを取得
- ダウンロードスクリプトで全ファイルをローカルに保存

### 段階的移行
- 一度に全ファイルを移行せず、段階的に実施
- 新規ファイルから新構造を適用
- 既存ファイルは徐々に移行

### アプリケーションの互換性
- 移行期間中は旧パスと新パスの両方に対応
- フォールバック処理を実装
