# タスク05: マイグレーション管理の導入

## 📋 概要
**優先度:** 🟡 中優先度（早めに対応すべき）

スキーマ変更履歴を追跡し、複数環境での同期を容易にするため、マイグレーション管理システムを導入する。

## 🎯 目的
- スキーマ変更履歴の追跡
- 複数環境（開発、ステージング、本番）での同期
- ロールバックの容易化
- チーム開発での競合防止

## ❌ 現在の問題

**影響:**
- スキーマ変更履歴が追跡できない
- 複数環境での同期が困難
- ロールバックが困難
- 手動実行による人為的ミスのリスク

## ✅ 改善案

### 1. マイグレーション管理テーブルの作成

```sql
-- マイグレーションバージョン管理テーブル
CREATE TABLE IF NOT EXISTS public.schema_migrations (
    version TEXT PRIMARY KEY,
    description TEXT NOT NULL,
    applied_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    applied_by TEXT,
    execution_time_ms INTEGER,
    checksum TEXT
);

-- マイグレーション履歴のインデックス
CREATE INDEX IF NOT EXISTS idx_migrations_applied_at 
ON public.schema_migrations (applied_at DESC);
```

### 2. マイグレーションファイルの命名規則

```
バージョン番号_説明.sql

例:
001_initial_schema.sql
002_add_timestamps.sql
003_jsonb_documentation.sql
004_composite_indexes.sql
005_storage_hierarchy.sql
```

### 3. マイグレーション実行関数

```sql
-- マイグレーションを記録する関数
CREATE OR REPLACE FUNCTION public.record_migration(
    p_version TEXT,
    p_description TEXT,
    p_applied_by TEXT DEFAULT current_user,
    p_execution_time_ms INTEGER DEFAULT NULL
)
RETURNS VOID AS $$
BEGIN
    INSERT INTO public.schema_migrations 
    (version, description, applied_by, execution_time_ms)
    VALUES 
    (p_version, p_description, p_applied_by, p_execution_time_ms);
    
    RAISE NOTICE 'Migration % applied: %', p_version, p_description;
END;
$$ LANGUAGE plpgsql;

-- マイグレーション状態確認関数
CREATE OR REPLACE FUNCTION public.check_migration_status()
RETURNS TABLE(
    version TEXT,
    description TEXT,
    applied_at TIMESTAMPTZ,
    applied_by TEXT
) AS $$
BEGIN
    RETURN QUERY
    SELECT 
        sm.version,
        sm.description,
        sm.applied_at,
        sm.applied_by
    FROM public.schema_migrations sm
    ORDER BY sm.applied_at DESC;
END;
$$ LANGUAGE plpgsql;
```

## 📚 マイグレーション管理のベストプラクティス

### 1. バージョン番号の付与ルール
- 3桁の連番を使用（001, 002, 003...）
- 説明的な名前を付ける
- 一度適用したバージョンは変更しない

### 2. マイグレーションファイルの作成ルール
- 1ファイル = 1つの論理的な変更
- 冪等性を保つ（複数回実行しても安全）
- ロールバック用SQLも用意

### 3. 実行順序の管理
- マイグレーションテーブルで実行順序を管理
- 依存関係を明確にする
- トランザクション内で実行
