## 📋 Supabaseチェック結果に基づく課題リスト

### 🔴 緊急対応が必要（セキュリティリスク）

#### 1. Security Definer Viewの修正
- **対象:** `v_example_contents_with_paths`, `v_index_usage_stats`, `v_word_meanings_with_paths`
- **問題:** セキュリティ定義ビューが権限エスカレーションのリスクを生む
- **修正方法:** [Security Definer View修正ガイド](https://supabase.com/docs/guides/database/database-linter?lint=0010_security_definer_view)
- **優先度:** 🔴 最高

#### 2. RLS無効テーブルの修正
- **対象:** `schema_migrations`テーブル
- **問題:** パブリックスキーマでRLSが無効化されている
- **修正方法:** [RLS有効化ガイド](https://supabase.com/docs/guides/database/database-linter?lint=0013_rls_disabled_in_public)
- **優先度:** 🔴 最高

#### 3. Function Search Path Mutableの修正
- **対象:** 30個の関数
- **問題:** search_pathが設定されておらず、SQLインジェクションのリスク
- **修正方法:** [Function Search Path修正ガイド](https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable)
- **優先度:** 🔴 高

### 🟡 重要だが緊急ではない（パフォーマンス・保守性）

#### 4. pg_trgm拡張のスキーマ移動
- **対象:** `pg_trgm`拡張
- **問題:** パブリックスキーマにインストールされている
- **修正方法:** [Extension移動ガイド](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public)
- **優先度:** 🟡 中

#### 5. Postgresバージョンアップグレード
- **対象:** supabase-postgres-17.4.1.064
- **問題:** セキュリティパッチが利用可能
- **修正方法:** [アップグレードガイド](https://supabase.com/docs/guides/platform/upgrading)
- **優先度:** 🟡 中

#### 6. RLSポリシーのパフォーマンス最適化
- **対象:** 5個のユーザー関連テーブル
- **問題:** auth関数の再評価によるパフォーマンス低下
- **修正方法:** [RLS最適化ガイド](https://supabase.com/docs/guides/database/postgres/row-level-security#call-functions-with-select)
- **優先度:** 🟡 中

### 🟢 最適化（パフォーマンス向上）

#### 7. 未使用インデックスの削除
- **対象:** 25個のインデックス
- **問題:** ストレージ使用量の無駄、メンテナンスコスト
- **修正方法:** [未使用インデックス削除ガイド](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index)
- **優先度:** 🟢 低

### 📊 監視・運用改善

#### 8. セキュリティ監査の定期実行
- **目的:** セキュリティ警告の早期発見
- **頻度:** 週次
- **優先度:** 🟡 中

#### 9. パフォーマンス監視の設定
- **目的:** パフォーマンス劣化の早期発見
- **頻度:** 日次
- **優先度:** 🟡 中

#### 10. データベース最適化の定期実行
- **目的:** 継続的なパフォーマンス維持
- **頻度:** 月次
- **優先度:** 🟢 低

## ⚠️ 実装時の重要注意事項

### バックアップ
- **全ての修正前に必ずデータベースのバックアップを取得**
- 特にセキュリティ関連の修正は慎重に

### テスト環境
- **本番環境での直接修正は避ける**
- 可能な限り開発環境で先にテスト

### ロールバック計画
- **各修正のロールバック手順を事前に準備**
- セキュリティ修正は特に影響範囲が大きいため注意

### 段階的実装
- **一度に全てを修正せず、段階的に実装**
- 各段階で動作確認を実施
