# 決定｜放置された匿名アカウントは180日で消す

決定日: 2026-09-18

## 決めること

ゲストは Supabase の匿名アカウントである
（[ゲストを「匿名アカウント」にする](guest-is-an-anonymous-account-20260907.md)）。
本番の Anonymous sign-ins は 2026-09-07 に ON になっている。

会員登録しないまま使われなくなった匿名アカウントを、いつまで残すかが決まっていない。
同じ決定の「人の手が要ること」と
[実行計画](../plans/guest-as-anonymous-account-plan.md) 7章に、保留として残っていた。

## 決めたこと

**最後に使ってから180日が過ぎた匿名アカウントは、学習記録ごと自動で消す。**

- 対象は `auth.users.is_anonymous = true` のアカウントだけ。メールとパスワードを
  足した会員は対象外である
- 「最後に使った日」は、その人の学習記録のうち最も新しい
  `public.user_card_progress.updated_at` とする。学習記録が1件も無い場合は
  `auth.users.created_at` を使う
- **`auth.users.last_sign_in_at` を単独で使ってはいけない。** 匿名サインインは
  保存済みセッションが無いときだけ走る（`AppState.startAnonymousSession`）。
  毎日使っている人も、この値は最初にアプリを開いた日のまま動かない可能性がある。
  これを起点にすると、現役の利用者の記録を消す
- 学習記録は一緒に消える。`auth.users` → `public.users` → `user_card_progress` が
  すべて `on delete cascade` でつながっているため、匿名アカウントを1件消せば、
  その人の記録も消える
- 削除は自動で行う。人が毎回判断する運用にはしない

## 今回やらないこと

- **削除の仕組みの実装。** 別チケットで作る。どこで動かすか（Edge Function、
  pg_cron、手動スクリプト）も、そのチケットで決める
- 本番データの削除。この決定は方針だけで、既存のアカウントには何もしていない
- 会員のアカウント削除。すでに実装済みで、対象外である

## 理由

**持ち主も入れない部屋が残り続ける。** 匿名アカウントへ入る手がかりは端末に保存された
セッションだけである。アプリを消す、端末を変える、データを消す、のいずれかで
その手がかりは失われ、二度と誰も入れない。放っておけば、実際の利用者数とは関係なく
増え続ける。

**180日にした理由。** 学習アプリなので、受験や学期の都合で数ヶ月あけてから戻る人がいる。
90日では、一学期休んだ人の記録まで消える。365日では、入れない部屋を1年抱えることになる。
半年あければ「戻ってくる人」はおおむね拾え、溜まり方も抑えられる。

**利用者にとっての損は小さい。** 消える相手は、180日間まったく使われていない
匿名アカウントである。戻ってきた人にはその時点で新しい匿名アカウントが作られ、
アプリは同じように使える。失うのは過去の学習記録だけで、会員登録した人の記録は消えない。

## プライバシーポリシーとの関係

[第9条](../legal/published/privacy-policy.md)1項は「アカウント情報および学習記録は、
ユーザーが本サービスを利用している間、保有します」と定める。使われなくなったものを
消すこの決定は、この条文と矛盾しない。

ただし条文は「何日で自動的に消す」とは書いていない。第9条は 2026-09-17 に
USL-315 で確定したばかりのため、日数を明記するかどうかは、この決定とは別に扱う。
**書き換えるとしたら、削除の仕組みを実装するチケットと同時にする。**
先に条文だけ変えると、書いてあるのに消えていない期間ができる。

## 影響

- [実行計画](../plans/guest-as-anonymous-account-plan.md) 7章の「放置匿名アカウントの
  保持期間」は決まった。同章から外す
- 削除を実装するチケットでは、次を満たす
  - 対象を `is_anonymous = true` に限る。条件を間違えると会員が消える
  - 「最後に使った日」の求め方を、上の定義どおりに実装する。実装前に、選んだ列が
    アプリを使うたびに本当に動くことを本番の値で確かめる
  - 先に件数を数えるだけの確認を通し、消す前に数を記録する
  - `auth.users` を消せば `public.users` と `user_card_progress` は連鎖で消える。
    表ごとに個別に消さない
