# 決定｜デッキごとに単語の主の意味を決める

決定日: 2026-09-14

## 決めること

[意味の行に活用と関連語を収める](senses-hold-forms-and-relations-20260914.md) により、
品詞が2つ以上ある287語は、`01_core_senses` で品詞ごとの行に分かれた（1000行 → 1288行）。

1つの単語に意味が複数あるとき、次の2点が決まっていなかった。

1. デッキは、どの単語をどの順番で持つのか。シートにはデッキの単語リストがない
2. 多義語のカードで、どの意味を主として見せるのか

## 決めたこと

**シートに `04_decks` と `04_deck_words` を足す。`04_deck_words` には、単語ではなく主の意味（`sense_id`）を書く。**

| 項目 | 決定 |
|---|---|
| `04_decks` | `deck_id`、`deck_name`、`concept_id` の3列。最初のデッキは `1, 大学受験頻出1000語, 1（simple）` |
| `04_deck_words` | `deck_id`、`sense_id` の2列。行の並びがデッキ内の並び順 |
| 主の意味 | `04_deck_words.sense_id`。カードで大きく表示し、例文・画像・音声もこの意味から出す |
| 副の意味 | 同じ単語のほかの意味。表示対象に含め、`priority` 順に並べる |
| DB | `cards` に `primary_meaning_id` を足す。`word_meanings (id, word_id)` への外部キーで、そのカードの単語の意味しか指せないようにする |
| 最初の1000語 | 主の意味は、各単語の `priority = 1` の意味（`sense_id` 1〜1000）。この意味にすべて例文がある |

## 理由

**主は、単語ではなくデッキが決める。** 同じ `increase` でも、受験のデッキでは動詞「増加する」、
経済のデッキでは名詞「増加」を主にしたいことがある。`01_core_senses.priority` は
単語の中での順番であり、デッキごとの違いを持てない。

**単語の列を持たない。** `sense_id` から単語は1つに決まる。`word_id` を別に書くと、
意味と単語が食い違う行を作れてしまう。

**カードのIDを変えない。** `cards` の一意条件は `word_id + card_template_id + deck_id` のまま。
主の意味はカードの属性なので、あとで変えても `user_card_progress` の学習記録は残る。
[`decks.concept_id`](../../supabase/migrations/20260913062500_add_concept_id_to_decks.sql) で
デッキが例文の世界観を決める設計とも合う。

## 影響

- [`source-database-v5.md`](../content/source-database-v5.md) を8シートの構成にし、2シートの列を書く
- USL-306: シートに2枚を足す（貼り付け用CSVは作成済み）
- USL-308: migrationで `cards.primary_meaning_id` を足し、取りこみで `decks` と `cards` を作る
- USL-309: 実機で、主の意味と、その例文・画像・音声が大きく出て、ほかの意味が副として出ることを確かめる
- アプリ: `WordCard.toCard()` は、いまは `priority` 順で最初に例文がある意味から例文を取る。
  `cards.primary_meaning_id` を読み、主と副を分けて表示するように直す（USL-309の前提）
- 主の意味に、デッキのコンセプトの例文がないと、カードに例文が出ない
- 例文の品詞が、つながっている意味の品詞と合っていない単語が13語ある
  （`limit`、`focus` など）。人間の判断で、いまは直さない
