# 決定｜画像と音声のファイル名に種類と6けたの番号を付ける

決定日: 2026-09-15

## 決めること

画像と音声のファイル名は、これまで `1.mp3` のように番号だけだった。
[音声のパスは取りこみが作る](audio-path-built-by-import-20260915.md) で決めた単語音声の形も、同じく番号だけである。
次の困りごとがあるため、名前の付け方を決め直す。

- 一覧で `1, 10, 100, 11` の順に並び、目で探しにくい
- 例文音声と単語音声がどちらも `1.mp3` になり、フォルダから出すと見分けられない
- 棚（`0000-0499` など）を500件ごとの計算で決める必要がある

## 決めたこと

**ファイル名は「種類 ＋ `-` ＋ 6けたの番号」にする。棚は番号の頭3けたにする。**

| 種類 | Storageパス | 例（番号1） |
|---|---|---|
| 例文画像 | `content-images/<theme-slug>/<棚>/example-<6けたの例文ID>.webp` | `content-images/simple/000/example-000001.webp` |
| 例文音声 | `content-audio/example/<theme-slug>/<棚>/example-<6けたの例文ID>.mp3` | `content-audio/example/simple/000/example-000001.mp3` |
| 単語音声 | `content-audio/word/<棚>/pron-<6けたの発音ID>.mp3` | `content-audio/word/000/pron-000001.mp3` |

| 番号 | 棚 |
|---|---|
| 1〜999 | `000` |
| 1000〜1999 | `001` |
| 2000〜2999 | `002` |

- 番号は、例文画像と例文音声は `example_id`、単語音声は `pronunciation_id`
- 6けたに足りない分は前を0で埋める。番号は999,999まで
- 同じパスへ別の中身を上書きしない。中身を変えるときは、番号を変えるか、古いファイルを消してから入れる

## 理由

**名前だけで何のファイルかわかる。** 種類を名前に入れるので、フォルダから出しても例文と単語を取り違えない。

**どこで見ても順に並ぶ。** けたをそろえると、文字の順と番号の順が同じになる。

**コンセプトが増えても足りる。** 例文はコンセプト（simple、ホラーなど）ごとに増える。4けたでは1万件で足りなくなる。

**棚を計算しなくてよい。** 名前の頭3けたが、そのまま棚の名前になる。

**上書きしないのは、古い中身が残るため。** 本番Storageのファイルは `max-age=3600` で配っている。アプリの画像キャッシュも、同じURLの画像を容量いっぱいまで持ち続ける。同じパスに上書きすると、利用者の端末に古い画像や音声が出続ける。

## 影響

- [`official-content-contract.md`](../architecture/official-content-contract.md) のStorageパスを書き直す
- アプリは変えない。パスはDBから読み、そのまま公開URLにする
- 取りこみ（USL-308）は、この形でパスを作る
- 本番にある古い名前のファイル150件（例文画像50・例文音声50・単語音声50）と、それを指すDBのパスは、
  1000語を入れるときに新しい名前へ置き換える。本番Storageと本番DBの変更なので、実行前に承認を得る
