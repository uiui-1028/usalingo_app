# 決定｜シートのIDは頭文字を付けず、これまでどおり数字にする

決定日: 2026-09-14

## 決めること

同じ日の決定 [シートのIDに頭文字を付け、1000語を一度に流す](sheet-id-prefix-and-1000-at-once-20260914.md)
では、シートのIDを `<頭文字>-<4桁>`（`w-0001` など）にし、取りこむときに頭文字を外すとした。
この頭文字を続けるかを決め直す。

## 決めたこと

**頭文字は付けない。シートのIDは、これまでどおり数字にする。**
シートの数字が、そのままSupabaseの整数IDになる。取りこみでIDを変換しない。

**番号はシートごとに1から数える。** 単語も意味も例文も `1, 2, 3…` と別々に付け、
ゼロ埋めはしない。千の位でシートを見分ける付け方（単語 `1001`、意味 `2001`、
例文 `3001`、発音 `4001`）はやめる。

前の決定のうち、IDに関する部分だけをこの決定で取り消す。次の部分はそのまま有効である。

- 活用・発音記号・派生語は、すでにある置き場を使う
- コンセプトは `simple` の1種だけ
- 1000語を一度に流す
- Notionの課題を3件（USL-306、USL-308、USL-309）にまとめる

## 理由

**DBでは、表ごとに番号が別になっている。** `words.id = 1` と `word_meanings.id = 1` が
同時にあってもぶつからない。外部キーは列ごとに参照先の表が決まっている。画像・音声の
パスもフォルダが分かれている。そのため、別のシートで同じ数字を使っても壊れない。

**変換をなくすと、道が短くなる。** シートの数字とDBの数字が同じなら、取りこみで頭文字を
外す処理が要らない。人がシートとDBを見くらべるときも、同じ番号で探せる。

## 影響

- [`source-database-v5.md`](../content/source-database-v5.md) の「IDの形」を、数字のIDに書き直す
- [`official-content-contract.md`](../architecture/official-content-contract.md) から、頭文字を外す説明を消す
- **千の位でシートを見分ける付け方をやめる理由。** この付け方では、1つのシートに999件までしか
  入らない。1000語だと意味や例文は999件を超えるので、番号の帯がほかのシートと重なる。
  重なるなら帯を持つ意味がないので、シートごとに1から数える
- **並び順は数字で決まる。** DBの `id` は整数なので、ゼロ埋めしなくても `1, 2, 10, 100` の順に並ぶ。
  `1, 10, 100, 2` の順に並ぶのは、列が文字型のとき
- 30語の確認用データ（`1001` などの番号）は、1000語を入れるときに1から付け直す
- **列の取りちがえに気づく手がかりが減る。** 意味の列に単語の番号を入れても、同じ番号の
  意味が存在すれば外部キーは通してしまう。取りこみ（USL-308）では、シートの列名と
  DBの列を1対1で対応させる
