### **✦ 取り扱い｜多義語順位**

*一つの単語が複数の意味を持つ「多義語」について、ユーザーが文脈に応じて意味を正しく理解し、記憶に定着させるためのUI/UXとコンテンツ提示戦略を定義する。*

---

**● 意味の判定基準**

異なる「意味」として `word_meanings` テーブルに登録する基準を以下のように定義する。

| **判定基準** | **具体例** | **usalingoでの取り扱い** |
| --- | --- | --- |
| **品詞が異なる場合** | **`book`**
・(名詞) 本
・(動詞) 予約する | 品詞が異なれば、意味も根本的に異なると判断し、**必ず別の意味として登録**する。 |
| **日本語訳が明確に異なる場合** | **`right`**
・(形容詞) 正しい
・(名詞) 権利
・(副詞) 右に | 文脈によって日本語訳が全く異なる場合は、**別の意味として登録**する。 |
| **コアは同じだが用法が異なる場合** | **`run`**
・(動詞) 走る
・(動詞) 経営する | コアイメージ（何かが連続して動く）は共通するが、用法として明確な違いがあるため、**別の意味として登録**する。 |

---

**● 意味の優先順位**

`word_meanings` テーブルの `priority` カラムに設定する値の決定ルールを以下のように定義する。

| **優先度** | **決定ルール** | **具体例** |
| --- | --- | --- |
| **1** | **最も一般的・基本的な意味** | `book` ならば、(動詞)「予約する」よりも **(名詞)「本」** の意味を最優先とする。 |
| **2** | **次に頻出する、または重要な意味** | `right` ならば、「正しい」や「権利」の次に **「右」** の意味を割り当てる。 |
| 3, 4, 5… | **専門的、または比喩的な意味** | `run` ならば、「走る」「経営する」の次に **「（水などが）流れる」** といった意味を割り当てる。 |

### **✦ 取り扱い｜語源／コアミーニング**

丸暗記を避け、深い理解を促すため、「語源」による論理的理解と「コアミーニング」による直感的理解をハイブリッドで提供する。

| **品詞カテゴリ** | **優先して格納する情報** | **具体例** | **理由** |
| --- | --- | --- | --- |
| **動詞** | **コアミーニング** | **`take`** → 自分の意思で対象を領域に取り込むイメージ | 意味の広がりを直感的に捉える方が学習効果が高いため。 |
| **前置詞** | **コアミーニング** | **`on`** → 何かに接触しているイメージ | 位置や方向の関係性を、イメージとして捉える方が応用しやすいため。 |
| **名詞** | **語源** | **`vision`** → vis (見る) + ion (こと) | 語彙を体系的に増やす上で、パーツの組み合わせとして論理的に理解する方が効率的であるため。 |
| **形容詞** | **語源** | **`visible`** → vis (見る) + ible (できる) | 語彙を体系的に増やす上で、パーツの組み合わせとして論理的に理解する方が効率的であるため。 |
| **その他** | **最も理解の助けとなる情報** | **`cool`** → 熱が取れ落ち着いたイメージ | 上記に当てはまらない場合は、より記憶に残りやすい方を柔軟に選択する。 |

### **✦ 取り扱い｜難易度**

*本アプリにおける単語の難易度は、CEFR-J のレベル定義に準拠して設計する。これは、ユーザーが自身のレベルを客観的に把握し、学習目標を設定する際の明確な指針を提供するためである。各レベルの解釈は以下の通り定義する。*

---

| **レベル** | **usalingo での解釈** | **概要** |
| --- | --- | --- |
| **A1** | **中学レベルの基礎** | 日常生活での非常に基本的な表現を理解し、使えるレベル。 |
| **A2** | **高校レベルの基礎** | 身近な事柄について、簡単で直接的な情報交換ができるレベル。 |
| **B1** | **大学受験レベル** | 日常的な話題について、主要な点を理解し、自分の意見を述べられるレベル。 |
| **B2** | **ビジネス基礎レベル** | 幅広い話題について、明確かつ詳細に自分の考えを表現できるレベル。 |
| **C1** | **ネイティブレベル** | 複雑な話題を理解し、流暢かつ自然に自己表現ができるレベル。 |
| **C2** | **専門家レベル** | 聞いたり読んだりした、ほぼ全ての情報を容易に理解できるレベル。 |

### **✦ 取り扱い｜コロケーション**

### **1. 基本方針**

- **目的**: 単語が実際の文脈でどのように使われるかを示すため、自然で慣用的な単語の組み合わせ（コロケーション）を提供する。
- **対象**: 全ての単語レコードに対し、コロケーション情報を付与することを原則とする。ただし、適切なコロケーションが存在しない場合は、この限りではない。
- **構造**: 各単語レコードに対し、複数のコロケーションを格納可能とする。データは、表示の柔軟性と将来の拡張性を考慮し、JSON形式で管理する。

---

### **2. データ構造**

- **カラム名**: `collocations`
- **データ型**: `JSONB`
- **構造**: 以下のJSONスキーマに準拠した配列を格納する。

```json
[
  {
    "category_jp": "string",
    "category_en": "string",
    "items": [
      {
        "phrase": "string",
        "translation": "string"
      }
    ]
  }
]
```

---

### **3. 各キーの定義**

| キー名 | データ型 | 必須 | 説明 | 例 |
| --- | --- | --- | --- | --- |
| category_jp | string | ○ | **日本語のカテゴリ名。**<br>「動詞 + 名詞」など、アプリでの見出しとして表示する。 | "動詞 + 名詞" |
| category_en | string | ○ | **英語のカテゴリ名。**<br>内部的なデータ管理や、多言語対応の際に使用する。 | "verb + noun" |
| items | array | ○ | カテゴリに属するコロケーションのリスト。 | [...] |
| phrase | string | ○ | **コロケーションのフレーズ。** | "take responsibility" |
| translation | string | ○ | フレーズの日本語訳。 | "責任を負う" |

---

### **4. コンテンツ作成ガイドライン**

- **カテゴリ分類**: 提供するコロケーションは、以下の優先順位でカテゴリ分けを行う。
    1. `動詞 + 名詞` (verb + noun)
    2. `形容詞 + 名詞` (adjective + noun)
    3. `副詞 + 形容詞` (adverb + adjective)
    4. `動詞 + 副詞` (verb + adverb)
    5. その他 (other)
- **選定基準**: 一般的な単語帳やコーパスで頻繁に見られる、学習効果の高い組み合わせを優先的に選定する。
- **例文**: 現バージョンでは例文を含めない。`phrase`と`translation`のペアのみを提供する。
- **表記**: `phrase`は全て小文字で記載する。冠詞（a, an, the）が必要な場合は含める。

---

### **✦ 取り扱い｜フレーズ／慣用句**

---

### **1. 基本方針**

- **目的**: 単語を含む、より大きな意味の塊である「定型句」や「慣用句（イディオム）」を提供する。これにより、ユーザーは会話や文章でそのまま使える実践的な表現を学習できる。
- **対象**: 全ての単語レコードに対し、関連するフレーズや慣用句を付与することを推奨する。
- **構造**: 各単語レコードに対し、複数のフレーズを格納可能とする。データはJSON形式で管理し、`phrase`（フレーズ）と`translation`（その訳）のペアで構成する。

---

### **2. データ構造**

- **カラム名**: `related_phrases`
- **データ型**: `JSONB`
- **構造**: 以下のJSONスキーマに準拠した配列を格納する。

```json
[
  {
    "phrase": "string",
    "translation": "string"
  }
]
```

---

### **3. 各キーの定義**

| **キー名** | **データ型** | **必須** | **説明** | **例** |
| --- | --- | --- | --- | --- |
| phrase | string | ○ | **フレーズ／慣用句そのもの。** | "take advantage of ~" |
| translation | string | ○ | フレーズの日本語訳。 | "〜をうまく利用する" |

---

### **4. コンテンツ作成ガイドライン**

- **棲み分け**: `collocations` プロパティが単語同士の**自然な相性**を扱うのに対し、`related_phrases` は**それ自体で意味をなす決まった言い回し**を扱う。
- **選定基準**:
    - **定型句**: `get in touch with ~` (〜と連絡を取る) のように、複数の単語で構成される決まった表現。
    - **慣用句（イディオム）**: `a piece of cake` (朝飯前) のように、単語本来の意味からは推測が難しい比喩的な表現。
    - **構文パターン**: `not only A but also B` (AだけでなくBも) のような、文法的に重要な構文も対象とする。
- **表記**:
    - `phrase`は全て小文字で記載する。
    - 文脈に応じて補足が必要な箇所は `~` や `...` を用いて示すことができる (例: `be responsible for ~`)。

---

### **✦ 取り扱い｜派生語**

- **目的**: 関連する単語を体系的に学習し、語彙ネットワークを構築するため、派生語（例：responsible, responsibly）の情報を提供する。
- **構造**: データは `JSONB` 形式で、以下のキーを持つオブジェクトの配列として管理する。
    - `word`: 派生語の文字列
    - `part_of_speech_jp`: 品詞（日本語）
    - `part_of_speech_en`: 品詞（英語）
    - `definition`: 簡単な意味

### **✦ 例文テキスト設計**

学習体験の中核をなし、記憶の定着を強力にサポートする「例文」の具体的なスタイルと制作方針を定義します。単なる情報の羅列ではない、「体験」としての学習コンテンツを設計するための憲章です。

---

### **✦** 設計思想

学習の継続を阻む最大の敵は「退屈」である。Usalingoは、信頼性の高い標準的な例文を基盤としつつも、ユーザーが任意で選択できる独自の「体験型コンテンツ」を競争優位性の源泉と位置づける。これは単なる例文ではなく、記憶へのフックとなるようエンターテイメント性を重視して創られたマイクロストーリーである。情景を捉えた高品質なイラストと連携することで、単語の意味を忘れられない「原体験」として刻み込むことを目指す。

### **✦ 例文イメージ仕様**

例文の情景を補完し、単語の意味を視覚的に刻み込む「イラスト」のスタイルと生成方針を定義します。各イラストは、対応するテキストテーマの世界観と一貫性を保つ必要があります。

---

### **✦ 例文イラストスタイル**

このテーマのイラストは、Midjourneyのバージョン`--v 6.1`を用いて生成する。視覚的な多様性を確保するため、スタイル参照（`--sref`）を用いない「基本スタイル」と、承認済みIDをランダムに引用して`--sref`を適用する「参照スタイル」の2種類を意図的に混在させる。プロンプトはGeminiまたはGPTsを介して最適化することで不適切な画像の生成率を抑える。

---

### **✦ 例文イラストスタイル**

このテーマのイラストは、アニメ調の表現に特化したNizijourneyを用いて生成する。ツール自体が持つ独自のスタイルを最大限に活かすため、追加のスタイル参照（`--sref`）は行わない。プロンプトはGeminiまたはGPTsを介して最適化することで不適切な画像の生成率を抑える。

### **✦ 例文イラストスタイル**

古典的な絵本を思わせる、温かみのある水彩画風のスタイル。柔らかい有機的な輪郭線と、落ち着いた色調を基本とする。キャラクターたちは表情豊かで親しみやすく、全体的にノスタルジックで居心地の良い雰囲気を目指す。リアルなディテールによる恐怖を呼び起こす画像を決して作らない。
