# 必ず調べる質問

## 学習開始

- 初回起動から最初の問題まで、利用者は何を選ぶ必要があるか。
- 登録、アンケート、教材選択、目標設定、学習モード設定は必須か、スキップ可能か。
- 2回目以降は前回の続きから始められるか。

## 1問の流れ

- 英単語、意味、イラスト、例文、音声は、どの順序と組み合わせで出るか。
- 答えを見る前に思い出す時間があるか。
- 正誤または自己評価を、何段階・どの操作で入力するか。
- 回答後、次の問題へ自動で進むか、操作が必要か。

## 学習終了と再開

- 1回の学習量を誰が決めるか。
- 予定分が終わったとき何を見せるか。
- 続ける、終わる、復習するなど、何を選ばせるか。
- 次回起動時、どこから再開するか。

## 信頼性とデータ

- 回答履歴や進捗は、ゲスト、ログイン後、端末間でどう扱われると説明されているか。
- オフラインや保存失敗について公式説明があるか。
- 分からない場合は推測せず「未確認」とする。

# 情報源のルール

- 現在の仕様は変わり得るため、必ずWeb検索で再確認し、調査日を記載する。
- 優先順位は、公式マニュアル／公式ヘルプ／公式サイト／App Store・Google Playの公式掲載情報／信頼できる実機レビューの順。
- 画面の細かな順序やタップ数は、文章・画像・動画で確認できた場合だけ「事実」とする。
- ストアの宣伝文を、第三者が検証した効果として書かない。「運営側の説明」と明記する。
- 重要な主張の直後に、直接開ける出典リンクを付ける。
- 投稿日や更新日が古い情報は、その旨を明記する。
- 同じ内容のまとめ記事を何本も並べず、一次情報を優先する。

# 事実の分類

すべての重要情報を次のいずれかに分けてください。

- 確認済み：出典から直接確認できたこと
- 推論：複数の事実から合理的に考えたこと
- 仮説：Usalingoで試す価値がある案
- 未確認：Webだけでは判断できないこと
- 反証：既存のH1〜H4に反対する材料

# 書き方

- 結論を先に書く。
- 長文を避ける。
- Markdownの `> [!IMPORTANT]`、`> [!NOTE]`、`> [!WARNING]` を重要な箇所だけに使う。
- 長い出典や補足は `<details>` で折りたたむ。
- 確認済み、推論、仮説、未確認を混ぜない。
- 「競合にあるから採用する」ではなく、Usalingoの利用者価値につながる理由を書く。

# やらないこと

- Usalingoの最終仕様を勝手に決定しない。
- Swift、データベース、API、ファイル名など実装方法を設計しない。
- 競合のUI、文章、イラストをコピーしない。
- 出典のない画面遷移、タップ数、学習効果を事実として書かない。
- コード、DB、Notion、既存Markdownを変更しない。調査結果はまず回答として提示する。
