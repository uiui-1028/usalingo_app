# USL-249 利用規約・プライバシー・ライセンス表示の棚卸し

最終確認: 2026-08-22
対象: 現行 SwiftUI (`apps/ios-swiftui/`) とリポジトリ内の migration・仕様・旧草案。
目的: 公開文書を作る前に、実装と根拠がそろっていること・不足していることを分ける。これは法的助言や公開規約ではない。

公開文書そのものの正本は [`published/`](published/) にあります。この文書はその根拠と不足を整理した調査結果です。

> [!NOTE]
> **2026-08-27 追記**: 「外部パッケージへ依存しない」という技術方針を撤回しました（[technology-stack.md](../operations/technology-stack.md)）。今後は画像キャッシュ等でSwift Packageを採用するため、OSSライセンス表示は「不要かもしれない項目」ではなく**公開前の必須項目**になります。収集の仕組みは [external-package-adoption-plan.md](../plans/external-package-adoption-plan.md) の領域1で扱います。この追記より下の本文は2026-08-22時点の調査結果です。

## 先に決めないこと

- 法律上の適法性、対象年齢、国外移転の同意方法、保存期間、会社名・窓口、コンテンツの再利用範囲は、責任者または専門家が決める。
- この調査では、利用規約・プライバシーポリシー・クレジット画面を公開しない。
- `supabase/migrations/` はローカルの設計・適用候補であり、本番の実データ、RLS、Storage 設定を確認した証拠ではない。

## 1. 現行アプリで確認できるデータと送信先

| 区分 | 現行コード・migrationから確認できること | 送信・保存先 | 表示・法務で確認すること |
| --- | --- | --- | --- |
| アカウント | メールアドレス、Supabase のユーザーID、アクセストークン、リフレッシュトークンを扱う。トークンは端末 Keychain に保存する。 | Supabase Auth、端末 Keychain | パスワード自体をアプリDBへ保存しないこと、Auth の実際の保持・リージョン・委託条件 |
| プロフィール | ニックネームとプランを読み書きする。画面にはメールアドレスを代替表示する。 | Supabase `user_profiles` API | `plan` の実際の値と課金連携の有無。現在のコードに課金SDKはない。 |
| 学習記録 | 正誤、復習日時・予定、習熟度、誤答数、反復回数、間隔を保存する。 | `user_card_progress` | 保存期間、退会後の扱い、利用目的、本人のデータ取得・削除の窓口 |
| 個人用の単語編集・タグ | 単語、意味、例文、画像パスの上書きとタグを保存できる。 | `user_word_overrides`、`user_word_tags` | 利用者入力の内容・削除手順。公開共有は現行コードでは確認できない。 |
| 公式コンテンツ | 単語、意味、例文、画像URL、音声URLを取得して表示・再生する。 | Supabase Database、公開 Storage URL | 各デッキ・例文・画像・音声の出典、権利者、改変可否、クレジット文言 |

現行コードでは Supabase の Auth / REST / 公開 Storage URL 以外のSDK、広告、分析、クラッシュ報告、位置情報・連絡先・カメラ・マイクへのアクセスは確認できなかった。これは「本番で一切収集しない」の保証ではない。App Store申請前に、ビルド設定、導入予定SDK、Supabase のログ設定も担当者が再確認する。

## 2. 退会・削除・保持

- `ProfileDashboardView` にある破壊的な操作はサインアウトだけで、Keychain のセッションを消す。アカウント削除、Supabase Auth の削除、サーバー上の学習記録の削除を開始する実装は確認できない。
- migration では利用者に紐づく `user_card_progress`、`user_word_overrides`、`user_word_tags` は `public.users` を参照して `on delete cascade` としている。実際に Auth アカウント削除が `public.users` を削除するか、バックアップ・監査ログをどう扱うかは未確認である。
- Apple はアカウント作成を支援するアプリに、アプリ内からアカウント削除を開始できる手段を求めている。削除に時間がかかる場合やサブスクリプションがある場合の案内も必要になる。公開前に削除フロー、保持が必要な情報、期限、問い合わせ窓口を責任者・専門家が確定する。根拠: [Apple: Offering account deletion in your app](https://developer.apple.com/support/offering-account-deletion-in-your-app/)

## 3. 第三者サービス・国外移転

- 現行実装が接続する外部サービスは Supabase である。`SUPABASE_PROJECT_REF` を用いて Auth、REST、公開 Storage URLへ接続する。
- 旧草案は米国等への移転を記載するが、実際の Supabase プロジェクトのリージョン、契約主体、処理場所、サブプロセッサ、ログ保持はこのリポジトリからは確定できない。
- 個人情報保護委員会の国外第三者提供の資料は、本人へ分かりやすい情報を示す重要性を説明している。公開する説明・同意の要否や内容は、実際の契約・リージョンをそろえて専門家が確認する。根拠: [個人情報保護委員会: 外国にある第三者への提供編](https://www.ppc.go.jp/files/pdf/251212_guidelines02.pdf)

## 4. 年齢・同意

- 現行の登録画面はメールアドレスとパスワードを入力できるが、年齢確認、保護者同意、利用規約・プライバシーポリシー同意のUIは確認できない。
- 旧プライバシー草案の「13歳以上」および13歳未満の保護者同意は、実装の裏付けがない。対象年齢、提供地域、子ども向け区分、必要な同意方法を決めるまでは公開文言へ転記しない。
- Apple の Kids Category を選ぶか、他地域へ配信するかで追加条件が変わり得るため、申請設定と専門家確認を先に行う。

## 5. コンテンツ・OSS・アセットの表示根拠

| 対象 | 確認済みの根拠 | 不足・次の確認 |
| --- | --- | --- |
| 単語リスト | 旧コンテンツ方針は NGSL / NAWL / BSL / TSL を CC BY-SA 4.0 と記載する。 | 実際に採用したデッキごとの出典URL、作者名、版、取得日、改変内容、CC BY-SA の継承対象を記録する。文書の記載だけで採用・配布権限を確定しない。 |
| 例文・画像・音声 | 現行契約は運営提供の例文画像（WebP）・音声（MP3）を公開 Storage で配信する設計。 | 個々の素材の作者・取得元・ライセンス・改変可否・クレジット要件は未記録。アップロード前に素材台帳を作る。 |
| アプリアイコン候補 | `assets/README.md` は候補素材が Xcode 未統合で、採用元・権利は未確定と示す。 | 採用前に各元データと生成物の権利・再配布可否を確定する。 |
| OSS | 2026-08-22時点では依存ファイルを確認できず、Apple標準フレームワークを主に使用していた。2026-08-27に外部パッケージ採用へ方針変更したため、この行は今後変化する。 | `Package.resolved` を正本として、追加のたびにライセンス本文とNOTICEを収集し、アプリ内のライセンス画面へ反映する。手作業ではなく生成の仕組みで維持する。 |
| ユーザー生成・AI生成物 | 現行SwiftUIで作成・共有する機能は確認できない。旧草案・AIGCガイドラインには共有、広告利用、削除・非表示の前提がある。 | その機能を追加するまで、これらの条項とクレジット説明は現行仕様として公開しない。追加時は投稿規約、通報、削除、第三者権利侵害対応を別途設計する。 |

## 6. 旧 Ver.1.0 草案との主な不一致

| 旧草案の記載 | 現行SwiftUIでの確認結果 | 扱い |
| --- | --- | --- |
| Proプラン、Apple/Google決済、月額・年額自動更新、返金 | 課金SDK・購入画面・ストア連携は確認できない。 | 削除または実装・ストア設定後に専門家確認。 |
| ユーザー生成デッキの共有、運営による削除・広告利用 | 現行コードでは共有・投稿・AI生成機能を確認できない。 | 現行の規約・ポリシーから除外し、将来機能として別チケット化。 |
| プロフィール画像・自己紹介 | 現行プロフィールはニックネームのみ。 | 収集項目から外す。追加時に再調査。 |
| 端末識別ID、OS、IP、操作履歴、Cookie、分析 | 現行iOSコードと依存設定からは収集SDKを確認できない。Supabase側ログは未確認。 | 「収集する」と断定して公開しない。運用設定を確認後に記載。 |
| 13歳基準・保護者同意 | 年齢入力・同意取得は未実装。 | 対象年齢と実装を先に決定。 |
| 退会手続とストア解約 | サインアウトのみ。アカウント削除開始手段は未実装。 | 削除フロー・保持期間を決めて実装後に記載。 |
| 当社名、責任者、メールアドレス | 旧草案に記載があるが、現行の事業主体・連絡先として未確認。 | 責任者が確定するまで公開しない。 |

## 7. 公開前の責任者・専門家向け確認リスト

1. 配信国、対象年齢、会社名・住所・問い合わせ窓口、課金の有無を確定する。
2. Supabase プロジェクトのリージョン、契約、ログ、バックアップ、Auth削除時の処理、保存期間を確認する。
3. アプリ内に、利用規約・プライバシーポリシーへの常時アクセス、登録時の同意、アカウント削除開始、削除完了/保持情報の案内を設計する。
4. 実際に配信する全デッキ、例文、画像、音声、アイコン、OSSについて、出典・作者・ライセンス・必要な表示・証憑を素材台帳へ記録する。
5. App Store Connect のApp Privacy回答を、アプリ本体だけでなく統合する第三者コードを含めて確定する。Apple はプライバシーポリシーURL、アプリ内の見つけやすいリンク、データ収集・第三者の取扱い・保持/削除の説明を求めている。根拠: [Apple App Review Guidelines 5.1.1](https://developer.apple.com/app-store/review/guidelines/)、[Apple App Privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)
